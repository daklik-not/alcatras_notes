Чтобы не приходилось вручную сканить сеть используется nmap.
#### Скан локальной сети
Чтобы узнать, какие устройства в сети используется:
```c
sudo nmap -sn 192.168.66.0/24 //ping scan but not ping(idk)
//sudo дает больше возможностей
```
Эта команда дает информацию о MAC адресах устройств - можно узнать вендоров сетевых карт. Nmap использует ARP запросы для выполнения этой команды - если устройство отвечает, значит оно активно

#### Скан удаленной сети
Под удаленной сетью имеется ввиду тот случай, когда устройства разделяет как минимум 1 маршрутизатор от нашей системы. В таком случае нельзя посылать ARP запросы. Все показано на картинке 
![[Pasted image 20260626185809.png]]
То есть nmap сначала делает ping, затем делает ping timestamp(),  tcp syn порт 445, tcp ack порт 80.


Есть еще команда 
```c
sudo nmap -sL 192.168.66.0/24 - показывает какие именно адреса будут просканены
```

#### Скан портов
Команда ниже фактически устанавливает TCP соединение - проводит тройное TCP рукопожатие. Она очень точная, но при этом очень легко распознается файрволлами.
```c
nmap -sT 192.168.1.66 
```
PS: Тут заметил забавную штуку. Windows файрволл не дает сканить. Но на компьютере с отключенным файрволом я уже получаю какие-то данные
```
PORT    STATE SERVICE
135/tcp open  msrpc
139/tcp open  netbios-ssn
445/tcp open  microsoft-ds
MAC Address: B4:2E:99:A9:A7:2B (Giga-byte Technology)
```
Теперь другая команда. Эта в свою очередь не выполняет рукопожатие полностью - только SYN пакет, и сразу после получения делает RST. Плюс в том, что меньше заполняются логи.
```c
nmap -sS 192.168.1.66 
```
Можно сканить и UDP порты. При неудачном установлении хост назначения шлет ICMP сообщение - так мы понимаем, что порт закрыт.
```c
nmap -sU 192.168.1.66
```
Чтобы просканировать 100 самых частых портов используется флаг "-F".
Чтобы просканировать диапазон портов -  "-p-100-200"- просканит от 100 до 200
Большинство стандартных сервисов запущено на первых 1024 портах

Чтобы обнаружить OS используется флаг "*-O"*.  Однако он не дает никакой гарантии, что ОС будет обнаружена верно и что она вообще будет обнаружена.

Чтобы получить более подробную информацию о приложении на хосте используется *-sV*.
Чтобы получить все вместе используется *-A*.

Иногда ICMP запросы по умолчанию отклоняются. В таком случае при использовании обычного -sS nmap посчитает, что хост оффлайн. Чтобы все равно попытаться устанавливать TCP соединение используется *-pN*

Чтобы задать время, используются флаги от -T0 до -T4. Полное сканирование при T0 будет выполняться 10 часов, а при T4 0.1 секунду. 

Чтобы настроить количество одновременных проб используется 
\--min/max-parallelism \<numprobes>
Можно также настроить частоту с которой посылаются пакеты(пакеты в секунду)
--min/max-rate \<number>
Время ожидания хоста 
--host-timeout

Чтобы получать подробности о том, как именно nmap ведет себя можно использовать флаг *-v*.  Максимальное количество *-vvvv*.  Чтобы получить еще более подробную информацию, можно использовать флаги от -d до -d9;

#### Сохранение репорта сканирования
Есть различные флаги для сохранение
```c
nmap -sS 192.168.139.1 -oA gateway
```
```
-oN - стандартный вывод
-oX - XML вывод
-oG - вывод, который можно легко обработать с помощью grep
-oA - вывод во всех главных форматах
```

#### То что встречалось на практике
```c
nmap -sL -n -oG - 192.168.1.0/24


-SL - просто листинг всех адресов
-n - отключить разрешение имен
-oG- grep-like формат
- - запись не в файл а в консоль
```
