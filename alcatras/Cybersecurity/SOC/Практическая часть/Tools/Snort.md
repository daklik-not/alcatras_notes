Оригинальные файлы Snort находятся */etc/snort*. 
Snort состоит из  *IPS - Intrusion Prevention Systems* и  *IDS - Intrusion Detection System*.  

Команды Snort
#### Запуск
```c
snort -V // проверка установлен ли snort
sudo snort -c /etc/snort/snort.conf -T // -c показывает что это файл конфигурации, -T тестирование конфигураци
```
#### Sniffer mode 
Перехват пакетов
```c
snort -v // отображает TCP/IP в консоль
snort -d // отображает данные пакета
snort -e // отображает заголовки канального уровня
snort -X // отображает заголовки в HEX
snort -i eth0 // параметр помогает выбрать интерфейс на котором перехватывать трафик
```
#### Packet Logger
Сохранения пакетов в PCAP. Лучше всего при создании папки с логами сразу прописывать *sudo chown your_user -R log_dir*, потому что по умолчанию у папки с логами root права
```c
snort -l // logger mode
snort -l -n // прочитает n пакетов потом завершится
snort  -K ASCII // логи в аски формате
snort -r // обозревает залогиненные события в snort
sudo snort -r logname.log icmp // отобразятся только пакеты с нужным протоколом
```

#### IDS/IPS режим
Кастомные правила находятся в local.rules. 
```c
-c // опредеение конфигурационного файла
-T // тестирование конфигурациооного файла
-N // отключениt логирования сетевых пакетов 
-D // Фоновый режим, используется в скриптах для автоматизации Snort
-A // режим алертов
```
Остановлюсь чуть подробнее на флаге -A
```c
-A console // алерты в простом стиле в консоли
-A cmg // полная информация о пакете, вызвавшем алерт в консоли
-A fast //  еще меньше информации, нет вывод в консоль
-A full // вся возможная информация об алерте
-A none // отключает алерты 
```

Можно запускать Snort только с пользовательскими правилами 
```c
sudo snort -c /etc/snort/rules/local.rules -A console
```

#### Структура правил  Snort
Вкратце показана на картинке
![[Cache/Pasted image 20260712212641.png]]Подробнее ниже
1. *Action*. Есть несколько типов действий.
	1. alert - создание алерта и логирование пакета
	2. log - логирование пакета
	3. drop - залокировать и логировать пакет
	4. reject - заблокировать пакет, логировать и завершить пакетную сессию.
	
2. *Protocol*. Snort поддерживает всего 4 протокола - IP, TCP, UDP , ICMP. Написано, что чтобы смотреть трафик прикладного уровня, надо просто смотреть нужный порт, например 80 для HTTP но это как-то странно - лучше искать явно хэдеры.

3. *IP && Port Numbers*
```c
192.168.1.56 any <> any any // источник 192.168.1.56 
192.168.1.0/24 any <> any any // источник все в подсети
[192.168.1.0/24, 10.1.1.0/24] any <> any any // источник несколько подсетей
!192.168.1.0/24 any <> any any // источник все, кроме этой подсети
any any <> any 1:1024 // диапазон портов от [1, 1024]
any any <> any 1025: // порт назначения >= 1025
alert tcp any any <> any [21,23] // порт назначения или 21 или 23
```
4. Направление потока
	 1. Поток от адреса назначения к адресу получателя:  **->**
	 2.  Двунаправленный поток. Полезно, когда используется что-то похожее на модель запрос-ответ. Пример: 
```c
- `alert tcp any any -> any 21` (на запросы клиента)
- `alert tcp any 21 -> any any` (на ответы сервера)
```

5. **Rule Options**. 
	```c
alert tcp any any <> any 80  (msg: "GET Request Found"; content:"|47 45   54|"; sid: 100001; rev:1;)
	```
	1. *Msg*  - это сообщение, которое вкратце описывает правило
	2. *Sid* - Snort Rule ID. Просто идентификатор правила. 1-100 - правила от разработчиков Snort.  \[100-999999\] - это то, изначально прилагалось к дистрибутиву. Все что больше это пользовательские правила. Sid должны быть уникальными
	3. *Reference*. Ссылка на правило или паттерн атаки - например указать номер CVE или ссылку на MITRE
	4. *Rev*.  Норме версии правила, который увеличивается каждый раз, когда правило изменяется. 
	 5.  **content:"GET"** - будет создавать алерт для каждого вхождение *GET* в пакет. 
	 6. nocase. Просто убирает *case-sensitive* для content
	 7.  fast pattern.  Ну короче когда несколько content явно указываем какую искать первой - по умолчанию берется просто самая длинная
	 8. id:123141 -  IP ID поле(которое используется для фрагментации)
	 9. flags:S - фильтруем по TCP флагам.  Короче там для каждого просто первая буква заглавная берется
	 10. dsize:min<>max; dsize:>100; dsize:<100;  Фильтрация по размеру пакета
	 11. sameip- когда src и dst IP совпадают

Главные компоненты Snort'a.
1. Декодер пакетов - собирает и подготавливает пакеты для препроцессинга
2. Препроцессор - компонент, который  организует и модифицирует пакеты для движка обнаружения
3. Движок обнаружения - анализирует пакеты и применяет правила
4. Логирование и алерты
5. Вывод в внешний источники(бд например) и дополнительные плагины

Правила Snort - есть 3 типа
1.  Правила от коммьюнити
2.  Правила за которые платить надо
3.  Бесплатные правила, но требующие регистрации
