Протокол Ди́ффи — Хе́ллмана
([англ.](https://ru.wikipedia.org/wiki/%D0%90%D0%BD%D0%B3%D0%BB%D0%B8%D0%B9%D1%81%D0%BA%D0%B8%D0%B9_%D1%8F%D0%B7%D1%8B%D0%BA "Английский язык") Diffie–Hellman key exchange protocol, DH) — [криптографический протокол](https://ru.wikipedia.org/wiki/%D0%9A%D1%80%D0%B8%D0%BF%D1%82%D0%BE%D0%B3%D1%80%D0%B0%D1%84%D0%B8%D1%87%D0%B5%D1%81%D0%BA%D0%B8%D0%B9_%D0%BF%D1%80%D0%BE%D1%82%D0%BE%D0%BA%D0%BE%D0%BB "Криптографический протокол"), позволяющий двум и более сторонам получить общий секретный [ключ](https://ru.wikipedia.org/wiki/%D0%9A%D0%BB%D1%8E%D1%87_\(%D0%BA%D1%80%D0%B8%D0%BF%D1%82%D0%BE%D0%B3%D1%80%D0%B0%D1%84%D0%B8%D1%8F\) "Ключ (криптография)"), используя незащищенный от прослушивания канал связи. Полученный ключ используется для шифрования дальнейшего обмена с помощью алгоритмов [симметричного шифрования](https://ru.wikipedia.org/wiki/%D0%A1%D0%B8%D0%BC%D0%BC%D0%B5%D1%82%D1%80%D0%B8%D1%87%D0%BD%D0%BE%D0%B5_%D1%88%D0%B8%D1%84%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5 "Симметричное шифрование").

Иными словами это набор действий, которые нужно совершить для того, чтобы получить общий (сессионный) секретный ключ, который затем можно будет безопасно использовать в алгоритмах шифрования. Стоит отметить, что данный протокол не подразумевает конкретного алгоритма шифрования, он нужен только для получения ключа. Ранее мы не рассматривали примеров симметричных шифров, но можете почитать про [AES](https://ru.wikipedia.org/wiki/AES_(%D1%81%D1%82%D0%B0%D0%BD%D0%B4%D0%B0%D1%80%D1%82_%D1%88%D0%B8%D1%84%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F): ключ выведенный по Диффи Хеллману можно будет использовать в в качестве ключа для AES.

Итак, перейдем к теории. В основе DH тоже лежит арифметика остатков и здесь тоже есть возведение в степень по модулю p, где p - простое число, g простым быть не обязано. Так как тема полей для новичка может показаться сложной, для простоты будем приводить в пример случайные числа p и g

Алгоритм выведения общего ключа достаточно прост:
1) берутся заранее публично известные обоим сторонам числа g и 
2) каждый пользователь (например Алиса и Боб) генерирует свое секретное число (a для Алисы и b для Боба)
3) при установлении соединения, Алиса отправляет следующее число бобу: $g^a \ mod \ p$
4) затем, боб отправляет алисе свое число $g^b \ mod \ p$
5) на данный момент у алисы есть число $g^b \ mod \ p$, а у боба есть число $g^a \ mod \ p$, для того, чтобы вывести общий секретный ключ, им достаточно возведи полученные числа в свою секретную степень и получить желаемое число - ключ (правда перед этим не забыть взять остаток от деления полученного числа на p). Здесь сделаем небольшое отступление.

---

Возьмем произвольное число g и возведем его в степень a, затем возведем полученное число в степень b, $(g^a)^b$. Вспомним, что по свойству степеней это эквивалентно $g^{ab}$ и эквивалентно $g^{ba}$. То есть, неважно в каком порядке мы будем возводить g в a, а затем в b, на результат это никак не повлияет. Ну хорошо, мы доказали, что $g^{ab} \ mod \ p = g^{ba} \ mod \ p$, а верно ли равенство, что $(g^a \ mod \ p) ^ b \ mod \ p = (g^b \ mod \ p) ^ a \ mod \ p$? Иными словами, имеем ли мы право применять полученное правило для остатков? Вы можете самостоятельно доказать это себе (например через разложение числа как nk + r). Но спойлер -- да, имеем
Таким образом, не передавая свою секретную степень (a для Алисы и b для Боба, Алиса и Боб смогли вывести общее секретное число)

Заметим, что несмотря на то, что 3 -- маленькое число, оно все еще может как ключ для шифрования. Однако для этого, нам эту тройку нужно "растянуть". Например с помощью KDF (Key Derviation Function) ([Функция формирования ключа](https://ru.wikipedia.org/wiki/%D0%A4%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D1%8F_%D1%84%D0%BE%D1%80%D0%BC%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F_%D0%BA%D0%BB%D1%8E%D1%87%D0%B0)). Например, md5(3) = eccbc87e4b5ce2fe28308fd9f2a7baf3. Здесь в роли KDF выступает хеш-функция md5.
