### Transport layer services
Транспортный уровень должен структурировать информацию.
1. Структуризация информации для приложений, работающих на хостах разных ОС, разных процессоров. Для этого требуется специальный синтаксис
2. Организовать взаимодействие между приложением и нижними уровнями. С точки зрения приложения - сеть это сервис транспортного уровня.

Транспортный уровень может предоставить 3 типа сервиса:
1. Connectionless сервис
2. Connection oriented сервис
3. Request-Response сервис
____
#### The connectionless service
Часто используется пользователями, которые обмениваются маленькими SDU.  Отправитель просто формирует пакет и отправляет его в сеть. Для больших и разных SDU нужен connection-oriented.при

#### The connection-oriented service
Вызов connection-oriented, далее CO, разделен на 3 части.
1. Установление соединения. Соединение - connection - временная связь между двумя пользователями через провайдера. После установления они используются для пересылки SDU. Обычно они обеспечивают один двухсторонний поток, между двумя связанными пользователями.
2. Поток используется для передачи данных во время второй фазы соединения, которая называется data-transfer фаза.
3. Завершение соединения - хост посылает запрос провайдеру на закрытие соединения.

#### Request-Response сервис
 В сети иногда полезно выполнять процедуру на другом хосте и получать результат вычислений - Remote Procedure Call.  В таком случае connection-less слишком ненадежный, а connection-oriented слишком медленный. Req-Resp позволяет эффективно обмениваться небольшими объёмами информации в запросе и связывать ее с ответом.
