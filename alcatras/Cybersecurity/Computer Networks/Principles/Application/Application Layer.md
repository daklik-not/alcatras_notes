Сетевые приложения организованы 2 способами
Первая модель: Client-Server. В этой модели сервер обеспечивают услуги клиенту, которые обмениваются информацией с ним.
![[Pasted image 20260226214235.png]]
Веб-сервер обеспечивает информацией в ответ на запрос пользователя.
Сервер принтера печатает документы, посылаемые клиентом.
С точки зрения разработчика клиент и сервер напрямую обмениваются сообщениями благодаря низлежащим уровням. Для регуляции работы при обмене запросами/ответами и сервер и клиент должны согласиться на набор синтаксических и семантических правил. 
За все это отвечает *application-level-protocol*. Есть 2 типа правил:
1.  Синтаксические правила - они точно определяют формат сообщений, которые обмениваются. Они определяют, как информация кодируется как битовые строки
2.  Организация потока информации. Поток структурирован и иерархичен. Например сервер должен получить имя пользователя и правильный пароль, до получения более сложных команд

***Синтаксические правила***
Протоколы прикладного уровня обмениваются 2 типами информации. Поскольку транспортный уровень  позволяет хостам обмениваться байтами, они должны договорить о стандартном представлении символов. Символы кодируются через ASCII таблицы + специальные символы(carriage return + LF+ Bell и другие). ASCII символы кодируются как поле из 7 бит, но передаются как 8битные биты, чей верхний бит установлен в 0. 
Строки могут быть и переменного размера и фиксированного. Стандартное решение  чтобы определить строку символов, с которой приложение может работать - задать ее с помощью *Backus-Naur-Form* - BNF. На картинке пример BNF

*Обмен чисел** 
Разные процессоры по разному хранят числа - *big-endian, little-endian*. Интернет выбрал big-endian. Такой порядок в сети называется *network byte order*. Библиотеки содержат функции для конвертации.

Некоторым приложениям нужно обмениваться структурами данных, содержащие битовые поля различной длины. Спецификация протокола будет определять такие сообщение через использования представления.
