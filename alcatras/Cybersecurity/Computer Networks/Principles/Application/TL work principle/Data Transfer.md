
Для надежной передачи данных транспортные протоколы включают в себя  sliding window и другие техники из канального уровня. Однако их недостаточно.
Скорость передачи не фиксирована, пакеты могут быть дуплицированы, доставлены не по порядку. Также транспортный уровень должен содержать механизмы преобразования больших SDU в SDU размером с пакет.
То, что осталось проверка на CRC - все поврежденные сегменты игнорируются.
Также используются *sequence number* и *acknowledgement number*. Sequence число отвечает за позицию первого байта потока байт. С помощью этого можно восстановить порядок и использовать это для реализации фрагментации. Используются 32битные или 64битные числа.
Поскольку сетевой уровень не гарантирует порядок, то транспортные протоколы используют *selective repeat* - #selective_repeat .

Объект транспортного уровня находится в ядре ОС. Он должен управлять множеством буферов пользовательских процессов. Для разных соединений разных приложений нужно создавать разные плавающие окна, выделять разное количество памяти на обработку.

**Sliding windows/Buffer size + Deadlock Problem soultion**
Чтобы справлять с проблемой, транспортные протоколы позволяют получателю положить размер текущего окна получения во все опознавания. Этот размер ограничивает размеры буфера отправителя. В любой момент момент времени число неопознанных сегментов не должно быть больше чем $min(swin, rwin)$. Получатель таким образом может ограничивать пропускную способность отправителя из-за своих недостатков памяти.

Чтобы решить эту проблему используется *persistence timer*. Короче говоря, если отправитель получил 0, и на протяжении какого-то времени не получает от него нового размера, он отправляет старый сегмент с целью получить размер окна через опознавание.

***Problems of unordered segments***
Если сегмент с определенным номером слишком долго шел до получателя, он может попасть в новый цикл sequence чисел, как показано на картинке.![[Cache/Pasted image 20260302011235.png]]
Чтобы решить это, во-первых используются 32битные числа, во-вторых используется MSL. Это ограничивает пропускную способность теоретически -  $2^n$ сегментов за MSL секунд, где n кол-во бит для кодировки
