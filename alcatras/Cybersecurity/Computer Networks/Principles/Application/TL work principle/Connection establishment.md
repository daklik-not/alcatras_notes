#### Connection establishment -  connection-oriented servic

Простейший подход для установления transport connection - определить два контрольных сегмента - CR(Connection Request), CA (Connection Acknowledgment). Очевидным образом, они обмениваются между собой ими для создания логики. Они содержат номер порта. Допустим их передача защищена аналогичными с канальным уровнем механизмами.
![[Pasted image 20260301232702.png]]

Это все равно не будет гарантировать надежность. Допустим пример - отправляется CR, CA устанавливается соединение. Отправляются данные, данные очень долго гуляют по сетевому уровню, настолько долго, что изначальный хост успевает отправить их еще раз. Старые данные доходят новые все еще гуляют по сети. Соединение закрывается, потом снова открывается и в этот момент приходят данные из прошлого соединения. Короче говоря, если обще описывать проблему - старые данные в новом соединении.

Чтобы избежать этой проблемы транспортный протокол определяет для сетевого уровня *Maximum Segment Lifetime - MSL*.  По этому протоколу гарантируется, что сегмент не находится в сети дольше чем должен. В интернете MSL - 2 минуты.
Чтобы определить дубликаты используются *transport clock*. Это k-битный счетчик с следующей формулой:
$$2^k * cycle >> MSL$$
Они должны увеличиваться на каждый цикл и на каждое установление соединения. Они должны увеличиваться даже, когда сущность передачи(хост) останавливается. Они не синхронизируются с реальными часами.

***Three way handshake***
Теперь эти часы используются в трехстороннем рукопожатии.
1. Объект передачи отправляет CR сегмент. Он содержит номер порта, и *sequence number=x*, чье значение забирается из транспортных часов. Передача защищена таймером перенаправления
2.  Удаленный объект обрабатывает CR сегмент и возвращает CA сегмент, который содержит номер опознавания(ack=x) и seq=y(чье значение забирается из транспортных часов).
3. Объект передачи получает CA сегмент. Номер опознавания этого сегмента подтверждает, что удаленный объект корректно получил CR. На этом этапе соединение считается установленным. Перед тем, как слать сегменты данных,, обьект передачи шлет CA 
4. Удаленный обьект рассматривает соединение как установленное, только после получения последнего CA.
