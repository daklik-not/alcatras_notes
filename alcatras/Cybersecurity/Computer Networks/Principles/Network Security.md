Доступ к множеству источников может получен через *malware*. Также могут быть уязвимости в протоколах.  Часто ответ, больше или намного больше запроса. Пример:

Боб обработает запрос и отправить большой ответ Алисе. Если запросы такого же размера, как и ответы - *reflection attack*.  При этом Мэллори остается анонимным для Алисы. ## Cryptographic primitives[](https://beta.computer-networking.info/syllabus/default/principles/security.html#cryptographic-primitives "Permalink to this headline")
Криптографические алгоритмы должны разрабатываться с тем учетом, что они могут стать известными. Их поведение должно контролироваться ключом, который известен только пользователям, которые хотят взаимодействовать.
Примеры:
Дан ключ $K$, теперь кодируем сообщение $M$ через вычисление $C_M = K \oplus  M$.  Восстановление делается с помощью -  $M = K \oplus (K\oplus M)$.  Это *шифр Вернама*. В реальности так плохо, потому что размер ключа должен быть равен размеру сообщения.
$$ \forall K, \forall M : D(K,E(K,M)) = M$$**AES - Advanced Encryption Standart**
Сейчас повсеместно используется. AES разделяет сообщение на блоки по 128 бит и использует ключи длиной 128, 192 или 256 бит. Если сообщение больше целочисленного количества, то оно просто добавляется до нужного размера. Благодаря 128 битным числам брут-форс сейчас практически невозможен.

Есть и другой стандарт - **public key cryptography**
1. Публичный ключ, который доступен каждому
2. Приватный ключ, который должен быть секретным для всех кроме тех, кому надо общаться между собой

Короче основная идея - cначала шифруем так
$$CM = E_P(A_{pub}, M)$$

Потом дешифруем так:
$$ D_p(A_{priv}, CM) = D_p(A_{priv}, E_{p}(A_{pub}, M)) = M$$
У меня есть заметка по RSA, где все это написано #rsa 
Можно вычислить *цифровая подпись сообщения* и с их помощью аунтефицировать сообщения. Если Алиса хочет подписать сообщение $M$ она может вычислить. Без криптографии любой может подделать адрес отправителя и назначения
$$ SM = E_p(A_{priv}, M) $$
Каждый, кто получает это подписанное сообщение, может выделить его контент, как
$$ D_p(A_{pub}, SM) = D_p(A_{pub}, E_p(A_{priv}, M)) $$
Типо шифруем по приватному ключу, дешифруем по публичному. Поскольку этот ключ известен только Алисе, возможность дешифровать SM доказательство того, что сообщение было подписано Алисой.

На практике шифровать все сообщение может быть очень дорого. Можно как-то резюмировать. Можно зашифровать чексумму, например. Но это плохо, потому что легко модифицировать сообщение так, чтобы чексумма совпадала. В реальности для подписей используются *криптографические хэш функции*. Она должна возвращать уникальное число для уникального сообщения. Также они демонстрируют *avalance effect* - маленькое изменение приносит большое изменение. Примеры - SHA-1, SHA-2, MD5.

Также ключи должны генерироваться максимально рандомно.

Алиса отправляет запрос на аунтефикацию, Боб отправляет рандомное число  Алисе. Алиса делает хэш по паролю и числу(*nonce*). Теперь подслушивающий не может просто отправить хэш и не может восстановить.
В это случае Боб должен хранить пароль Алисы в чистом виде - любая брешь в безопасности компьютера Боба приведет к утечке паролей.

*Цепочки хэшей*
Лучше не хранить пароль в явном виде. Для этого Алиса вычисляет *hash chain*. Hash chain - последовательность применений хэш-функции над строкой $H(H(H(P)))$. Результат цепочки будет сохранен на компьютере Боба вместе с длиной цепочки. Боб посылает Алисе нужное число прохождений по цепочке, она вычисляет ее и посылает информацию Бобу. Боб подтверждает и уменьшает значение на 1. Из-за уменьшения подслушивающий не может просто взять и отправить полученный хэш
Очевидно что вышеописанное не работает для атаки типа MITM - цепочки хэшей должны использоваться только там где есть гарантия, что не будет MITM.

*Подход с публичной криптографией*
Алиса знает публичный ключ Боба, и Боб также знает публичный ключ Алисы. Алиса посылает запрос на аунтефикацию,  Боб отправляет  $E_p(Alice_{pub}, R)$ - рандомное число, зашифрованное ключом Алисы. Алиса дешифрует по своему ключу, шифрует по ключу Боба, боб дешифрует и получает искомое число - подтверждение авторизации.

Криптография по публичному ключу часто сочетается с *сертификатами*. Сертификат это структура данных, которая включает сигнатуру от доверенного стороннего источника. Сигнатура это зашифрованная по закрытому ключу сертификационного центра данные. Условно структура сертификата состоит из:
1. Идентификационного номера хоста

3. Зашифрованные *приватным ключом* СЦ 1-2 поля.
Таким образом, для подтверждение личности, устройства с *открытым ключом СЦ* могут дешифровать *подпись сертификата*

## Key exchange[¶](https://beta.computer-networking.info/syllabus/default/principles/security.html#key-exchange "Permalink to this headline")
Надо уметь обмениваться ключами, даже когда есть прослушиватель в сети. 
Для этого используется алгоритм Diffie-Hellman. У меня есть про него заметка уже, но я здесь еще раз напишу, вспомню. #diffie-hellman
Диффи-Хеллман оперирует большими числами.. 
Берутся 2 заранее известных публичных числа $g,p$ причем такие, что $g$ - простое число, а $p$ - первообразный корень $g$

___
Первообразный корень(по модулю простого числа $p$) - это такое число $g$  степени,  которого порождают все ненулевые числа по модулю $p$. 
____
Обмен происходит следующим образом:
1. Алиса выбирает случайное число $a$ и посылает $A=g^a \mod p$. 
2. Боб выбирает случайно число $b$ и посылает $B = g^b \mod p$
3. $Secret = A^b \mod p = (g^b \mod p)^a \mod p = g^{a * b} \mod p$
4. $Secret = B^a \mod p = (g^a \mod p)^b \mod p = g ^{a * b} \mod p$

Поскольку сами случайные числа по сети не отправляются, то тяжело вычленить $a, b$ - таким образом, чтобы получить  $g ^{a * b} \mod p$

К сожалению полностью проблему это не решает.
Допустим Мэллори сидит посередине - может отлавливать и изменять сообщения.
1. Алиса выбирает секретное число и посылает $A = g^a \mod p$ Мэллори
2. Мэллори генерирует секретное число $m$ и посылает $M = g^m \mod p$ Бобу
3. Боб выбирает секретное число и посылает $B = g^b \mod p$ Мэллори.
4.  Мэллори вычисляет $S_a = M^a \mod p$ и $S_b = B^m \mod p$
5. Алиса вычисляет $S_a = m^a \mod p$  и использует его чтобы говорить с Мэллори
6. Боб вычисляет $S_b = M^b \mod p$ и взаимодействует с Мэллори.

Таким образом Алиса шифрует $S_a$ - а Мэллори дешифрует и посылает Бобу. Боб дешифрует через $S_b$. 

Чтобы безопасно использовать Диффи-Хеллман, Алиса и Боб должны быть аутентифицированы.  Для этого можно использовать сертификаты.
