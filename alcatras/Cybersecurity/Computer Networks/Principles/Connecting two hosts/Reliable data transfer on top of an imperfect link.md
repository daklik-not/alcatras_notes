DataLink уровень должен справляться с ошибками передачи:
1.  Кадры могут быть повреждены ошибками передачи
2. Кадры могут быть потеряны, или созданы ненужные кадры

Может быть несколько типов ошибок
1.  Значение одного бита было изменено
2.  N последовательных бит были изменены
3.  Создание и пропажа рандомных битов.

Единственный способ решить это, добавить какую-то избыточную информацию, по которой получатель может обнаружить/скорректировать ошибки передачи.

*Coding Schemes*
Схемы кодирования. Схема кодирования это функция которая сопоставляет информацию закодированную как строку из m бит в строку из n бит.
Самая простая схема, просто добавить один бит так, чтобы сумма последовательности битов всегда была четной. По этой схеме можно обнаружить ошибку одного бита, но не нескольких + нельзя починить.

*TMR (Triple Modular Redundancy*
Один из примеров избыточного кодирования - пусть 1 кодируется как 111, а 0, как 000. Какое число будем решать по принципу й. Каких символов дойдёт больше, за то и голосуем. Очевидно работает только для 1 ошибки. Помимо *TMR* есть другие мощные коды коррекции ошибок, например *Hamming Code* (там много математики)) - умная комбинация parity битов, которая обеспечивает обнаружение ошибок, и возможности коррекции,

**Error detection code**
Канальный уровень включает в себя некоторые механизмы защиты. Используется error detection code. Это такая функция от самого сообщения. Отправляется сообщение и EDC. Потом получатель заново считает EDC по сообщению и сравнивает его с тем, которые пришел. Если они равны то все ок. 
*Пример* Допустим есть строка из n бит. Добавим к ней r бит. EDC функция вычисления r бит по n бит. 
Самый простой код обнаружения ошибки это parity бит. Избыточный бит выбирается таким образом, чтобы количество бит в n+r строке было четное/нечетное. Получать может легко перепосчитать parity битовой строки. Очевидно он также работает только для 1 ошибки.
Аналогично с *чексуммой* - просто посчитаем сумму бит, и сравним ее с той которую посчитал отправитель.
Сейчас используется *CRC - Cyclical Redundancy Checks*. N битный CRC может обнаружить все ошибки передачи, количеством менее чем N бит и все ошибки передачи, которые повлияли на нечетное количество бит(с правильно выбранным полиномом). Про CRC там тоже математика жесткая, неохота пока разбирать ее. Помимо сетей CRC используется для дисков.
EDC хранятся в заголовке.

Очевидно, что если данные повреждены, то лучше их перенаправить. Повторная передача должна произойти после ожидаемого времени получения сигнала опознавания

Alternating Bit Protocol - ABP
1.  Изначально ждем DATA.req. Первый кадр использует порядковый номер 0. Далее отправитель ждет сигнала опознавания.
2.  Получатель ждет кадр вида D(0). Далее проверяется *CRC*.  Поврежденные кадры просто игнорируются. Если данные корректные посылается OK0 и данные отправляются пользователю. Далее получатель ожидает D(1,...). При получении D(0, ...) получатель отправляет OK0, чтобы получатель мог восстановиться. 
![[Pasted image 20260217223141.png]]
Проблема ABT в том, что он такой медленный.

Главная проблема ABP - он медленный. Таймер опознавания может быть достаточно долгий, а следующий кадр просто не отправится до этого момента.
Эту проблему можно решить с помощью конвейеризации. Идея в том, что отправитель не будет ждать сигнала опознавания для отправки следующего пакет. Номер пакета, это какое-то число.
У конвейеризации есть своя проблема - пакеты от отправителя могут сильно загрузить получателя - он не будет успевать их обрабатывать. Для решения этой проблемы придумали *sliding window - классика)*. Окно мапится на упорядоченную последовательность чисел.  Отправлять кадры можно только с номером, который в окне. Если для всех трех номеров кадров не пришел сигнал опознавания, окно не будет двигаться. Как только сигнал опознавания приходит, окно можно подвинуть на 1 элемент вправо.Все на рисунке короче.

Go-back-n восстановление
Очевидно, протоколу нужно как-то обнаруживать ошибки и перенаправлять кадры. 
*Reciever*
*go-back-n*игнорирует любые непоследовательные номера, которые он получает. Также при неправильном кадре всегда отправляется номер последнего обработанного кадра. Когда кадр нормальный он возвращает номер последнего полученного кадра. Если кадр опознавания теряется, то последующие кадры опознавания говорят получателю о том, что предыдущие кадры были обработаны. 
*Sender*
Когда sender  получает опознавание, он убирает из буфера отправки все опознанные кадры. После отправки первого кадра запускается кадр опознавания. Таймер перезапускается только в том, случае, когда остались неопознанные кадры в буфере. Когда таймер заканчивается, все неопознанные кадры в буфере считаются потерянными. Их снова отправляют.

Преимущества go-back-n - простая реализация, при небольших потерях выдает хорошую производительность.

#selective_repeat
Selective repeat — выборочное повторение

Получатель при получении кадра сначала проверяет, входит ли его порядковый номер в текущее скользящее окно. Если входит, кадр помещается в буфер получения и отправляется подтверждение для этого кадра; если не входит — кадр игнорируется и отправляется подтверждение с номером lastAck. В данном протоколе lastAck — это номер последнего последовательно полученного кадра, то есть такого, для которого получены все предыдущие кадры без пропусков. После каждого нового принятого кадра получатель проверяет, образовалась ли непрерывная последовательность начиная с lastAck + 1; если да, все такие кадры удаляются из буфера, передаются выше по стеку, lastAck обновляется, и окно сдвигается вперёд.

Отправитель реализует буфер отправления, который может хранить не более W неподтверждённых кадров. Кадры передаются до тех пор, пока число неподтверждённых кадров меньше размера окна; при заполнении буфера отправка приостанавливается. Для каждого отправленного кадра запускается отдельный таймер переотправления, который отменяется при получении соответствующего подтверждения. Если таймер истекает, переотправляется только данный кадр. При получении подтверждения кадр удаляется из буфера отправления, окно при необходимости сдвигается, и отправитель получает возможность передавать новые кадры. 
В качестве дополнительной информации можно отправлять, например, список всех полученных кадров.
