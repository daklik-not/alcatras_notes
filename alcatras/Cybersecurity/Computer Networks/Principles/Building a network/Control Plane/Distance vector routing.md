#### Distance vector routing - маршрутизация с использованием вектора расстояния
Каждый роутер реализует таблицу маршрутизации. Таблица маршрутизации R для адреса назначения d хранит.
```
R[d].link - выходящий канал, по которому отправится пакет
R[d].cost - стоимость отправки
R[d].time - временая метка, когда вектор расстояние послдений раз получал информацию по адресу d
```
Роутер регулярно посылает свой вектор расстояния на все интерфейсы. Этот вектор является обобщением таблицы маршрутизации роутера, которая показывает расстояние между каждым известным назначением. Псевдокод ниже:
```c
Every N seconds:
    v = Vector()
    for d in R[]:
        # add destination d to vector
        v.add(Pair(d, R[d].cost))
    for i in interfaces
        # send vector v on this interface
        send(v, i)
```
При получении вектора расстояния по каналу l роутер обрабатывает его примерно так:
```c
# V : received Vector
# l : link over which vector is received
def received(V, l):
    # received vector from link l
    for d in V[]
        if not (d in R[]):
            # new route
            R[d].cost = V[d].cost + l.cost
            R[d].link = l
            R[d].time = now
        else:
            # existing route, is the new better ?
            if ((V[d].cost + l.cost) < R[d].cost) or (R[d].link == l):
                # второе условие отвечает за изменение текущего маршрута
                R[d].cost = V[d].cost + l.cost
                R[d].link = l
                R[d].time = now
```
При инициализации просто от каждой вершины пускаем dfs, так инициализируем для каждой вершины таблицу маршрутизации.

**Работа при ошибке**
Если временная метка маршрута не обновлялась более чем N секунд, значит есть какие-то проблемы. Если временная метка не обновлялась 3\*N секунд то этот маршрут нужно убрать.
При ошибке роутер оповещает соседей(присваивая inf стоимость).

 Допустим канал AB ломается. Тогда A оповещает соседей, которые восстанавливают свои таблицы, потом соседи оповещают других соседей и через какое-то время все восстанавливается, просто другим путем. Это пример, когда распадается на 1 компоненту.
 
*Сount to infinity problem*
Теперь допустим  после этого ломается канал DE. Рассмотрим ситуацию, когда вектор расстояний A приходит быстрее чем D отправляет свой вектор расстояний. В таком случае, D изменит свой вектор расстояний. Тогда D будет думать, что вершина B достижима через A добавляя лишнюю вершину -     Короче говоря из-за того, что A думает, что оно достигает вершины через D, а D думает, что оно достигает вершины через A все зациклится и будет бесконечно расти. Это называется *count to infinity problem*. По факту она возникает в любой цикличной сети.

Чтобы ее решить используется следующая техника. Роутер будет создавать вектор расстояний, который специфичный для каждого соседа и содержит маршруты не полученные от этого соседа. Код примерно такой. Единственное, что я так и не понял, зачем при такой реализации вот это условие  (R[d].link == l). Оно бесполезное поскольку просто изменение стоимости одного ребра между соседями не будет обновляться. Тем не менее даже так это не фиксит все случаи.

Every N seconds:

            if (R[d].link != l):
