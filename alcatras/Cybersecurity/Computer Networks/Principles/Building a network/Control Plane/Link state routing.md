#### Link state routing
*Link-state* маршрутизация. Роутеры обмениваются сообщениями, чтобы позволить каждому роутеру знать всю топологию сети. Основываясь на топологии можно юзнуть дийкстру и посчитать самый хороший путь.
Сеть - направленный взвешенный граф. В качестве веса могут быть выбраны разные значения:
1. Количество роутеров между.
2. Вес пропорциональный задержке распространения канала.
3. $C / bandwidth$ - C - большая константа.

Когда link-state роутер запускается, ему сначала надо изучить, какие роутеры напрямую соединены. Каждый роутер каждые N секунд посылает Hello сообщение, которое содержит адрес роутера. У каждого роутера уникальный адрес. Эти сообщения посылаются только соседям. Если сообщение не приходит в течение k\*N секунд - канал сломался.

Чтобы узнать топологию сети роутер создает **LSP пакет**. Он содержит следующую информацию
1. LSP.Router - идентификатор отправителя LSP
2. LSP.age - age или оставшееся время LSP
3. LSP.seq - число последовательность LSP
4. LSP.Links[] - каналы в LSP. Каждый канал содержит идентификатор соседа и вес.

**Flooding algo**
Нужно уметь вычислять LSP без таблиц маршрутизации. В этом алгоритме каждый роутер, который реализует flooding создает *link state database(LSDB) - база данных состояний каналов*, которая содержит самые недавние LSP отправленные каждым роутером. Когда роутер получает LSP, он проверяет есть ли оно в LSDB. Если да, пересылать его в сеть не надо. Если нет, то пересылает его всем соседям. Псевдокод ниже
```c
if newer(LSP, LSDB(LSP.Router)) :
    LSDB.add(LSP)  # implicitly removes older LSP from same router
    for i in links:
        if i!=l:
           send(LSP,i)
```
Чтобы понять, какое число больше и не допустить ошибок используется сравнение чисел + CRC.
Короче говоря последовательность такая
1. Роутер обменивается hello сообщениями с соседями, после чего высчитывает свой LSP.
2. Роутер посылает этот LSP на все каналы.
3. Роутеры, которые получают LSP, добавляют их в свой LSDB.
4. Роутеры отправляют этот LSP дальше по сети, обычно с небольшой задержкой.

*Reliable flooding*
С надежным флудом роутеры используют опознавания/перенаправления
Благодаря надежной передаче каждый роутер может построить граф отображающий надежную топологию.

Когда роутер понимает, что канал отсутствует, он начинает флудить новым LSP. Очевидно, что нужно время, пока до всех в сети дойдет актуальная версия LSP. Когда роутер ломается, убираются все ребра направленного графа, которые идут к нему, значит через него нельзя ничего передать. С помощью поля age, по мере истечении времени записи LSP убираются.

При вычислении таблицы пересылок используется дийкстра.
