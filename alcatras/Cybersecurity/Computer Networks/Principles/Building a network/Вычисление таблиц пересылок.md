#### Вычисление таблиц пересылок
 Есть несколько техник обновления таблицы пересылок по приходу пакета.

#### 1. Сеть - дерево
Приходит пакет,  мы получаем его источник, проверяем в таблице пересылок на наличие его адреса. Когда вершина дерева получает пакет по заданному интерфейсу, она должная понять что адрес этого пакета достижим по этому интерфейсу. Вершина реализует структуру данных, которая сопоставляет каждый адрес источника с тем, что пришло по интерфейсу. Эта структура данных называется *port address table*, а сам интерфейс портом.
Короче говоря мы сопоставляем адрес источника входящего пакета с интерфейсом, таким образом говоря, что этот адрес доступен по этому порту.
Насколько я понял под интерфейсом здесь подразумевается физический интерфейс, вроде сетевой карты. Раз мы говорим про роутеры - у них много таких интерфейсов.
Если адрес назначения не включен в *port address* таблицу, то вершина просто расслыает пакет по всем интерфейсам, исключая тот, откуда пакет пришел(смысла нет возвращаться назад, ну как дфс короче). Рассылка по всем интерфейсам называется *broadcasting*. 
Эта техника используется в *Ethernet сетях*

Есть 2 недостатка
1. Трансляция сама по себе дорога, особенно если адрес назначения пакета не в сети
2. Мало сетей имеют древовидную форму. На картинке показана структура с циклом. R1 получит пакет от A, транслирует его - пакет получают  R3 и R2,  они тоже транслируют пакет, пакет получает R1 и B - таким образом оно циклится и падает. При такой архитектуре инженеры сети должны убедиться в том, что нет циклов

####  2. Source routing
Интуитивно *маршрутизация с заданным источником* позволяет назначению автоматически исследовать пути для заданных источников. Каждой вершине определяется одним уникальным адресом и одним идентификатором на выходящий маршрут.
![[Pasted image 20260223170439.png]]

При запуске вершина посылает специальный контрольный пакет, через который она оповещает свои адреса соседям. Когда вершина получает такой пакет, она автоматически отвечает со своим собственным адресом. 

С *source routing* пакеты плоскости данных включают в себя список идентификаторов. Этот список называется *source route* - он определяет путь, который пакеты надо пройти как последовательность идентификаторов каналов. Когда вершина получает такой *пакет плоскости данных*, она сначала проверяет,  является ли адрес назначения прямым соседом.  В этом случае пакет направляется соседу. В другом случае  вершина выделяет следующий адрес из списка отправляет его соседу. Зная всю сетевую топологию источник может легко высчитать путь, однако зачастую у источников нет доступа ко всей карте сети.

В сетях которые используют *source* маршрутизацию, хосты используют пакеты управления для того, чтобы автоматически исследовать сеть на лучшие пути. Пакеты управления содержат адрес источника, назначения и список вершин между ними. Этот список часто называется *маршрут записи*. Когда вершина получает контрольный пакет, она проверяет, есть ли она в этом списке. Если да то пакет просто игнорируется. Иначе, пакет транслируется на все интерфейсы, исключая обратный.
