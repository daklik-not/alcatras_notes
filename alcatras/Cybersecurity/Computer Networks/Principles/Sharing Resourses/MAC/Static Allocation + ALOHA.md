#### Static allocation
Допустим возможности канала a, тогда a/N - часть выделенной пропускной способности на каждое устройство.
Такое выделение можно делать и в беспроводной сети. Определенный диапазон частот резервируется одним приложением, другой другим
***FDM*** - Frequency Division Multiplexing,  Полоса пропускания разбивается на  диапазоны частот, и каждый диапазон присваивается определенному устройству. ***WDM*** -  Wave-length division Multiplexing - то же самое но для света. Передается свет с разными волнами.
***TDM***  -  Time Division Multiplexing. Разобьем время канала на слоты. В каждый слот будет отправлять по байту для каждого из устройств. О порядке байт два устройства должны договориться с помощью контрольных пакетов. С их же помощью можно все это регулировать динамически

Проблема статичной аллокации в том, что компьютеры общаются в режиме on-off. В период on они пытаются максимально загрузить сеть, в режиме off простаивают. Это просто не эффективно для статичного выделения.

#### ALOHA
До ALOHA сети только по кабелям ТБ или физическим кабелям. Смысл ALOHAв том, что пакеты обменивались с помощью *радио технологии*.
Терминалы и мэйнфреймы обменивалсь кадрами фиксированной длины. Два канала в 400МГц диапазоне были использованы - для мэйнфрейм- устройство и наоборот.
Все терминалы делили канал - риск коллизий. Проверялись биты четности, и если они плохие посылалось опознавание. Те в свою очередь через рандомно выбранный промежуток перенаправляли кадры.
```
N = 1
while N <= max:
    send(frame)
    wait(ack_on_return_channel or timeout)
    if (ack_on_return_channel):
       break  # transmission was successful
    else:
             # timeout
             wait(random_time)
             N = N + 1
else: - сликом много ретрансмиссий
```

К ней применялось множество модификаций, например *the slotted technique*. Он разделил время на слоты, и позволил терминалам отправлять только в начале каждого слота. Часы могут быть общие на сервере.
