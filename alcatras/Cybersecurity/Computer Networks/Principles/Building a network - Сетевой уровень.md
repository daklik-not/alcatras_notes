Хостам часто надо взаимодействовать с другими хостами, которые напрямую не соединены по проводу. Для этого нужен **сетевой уровень**. Главная задача сетевого уровня  - позволить устройствам из разных сетей общаться между собой через **роутер**. Юнит информации - **пакет*

Есть несколько проблем при передаче данных только канальным уровнем
1. Разные канальные уровни c разным максимальным размером.


Помимо этого есть главная проблема. Когда одно устройство передает кадр роутеру(задача которого, передавать данные между хостами), он должен понимать, какому устройству требуется кадр. Этим и занимается сетевой уровень. Он идентифицирует устройства в сети и позволяет передавать информацию, которые соединены не напрямую, через роутеры между ними. Информация, нужная для идентификация помещается в *пакет* вместе с пользовательскими данными. На сетевом уровне каждому элементу присваивается адрес в сети - обычно последовательность бит, чаще всего адрес фиксированной длины.

Точный формат пакетов и таблица пересылок - часть *data plane - плоскость данных* сети.  Плоскость данных содержит все протоколы и алгоритмы сетевого уровня, которые занимаются обработкой и созданием пользовательских данных. На роутерах провайдеров/транзитных провайдеров часто плоскость данных вшита в hardware для ускорения.  
Другая плоскость - *control plane*. Она содержит все протоколы и алгоритмы, часто распределённые, которые высчитывать таблицы пересылок внутри сети. Сети с одной и той же технологией могут использовать различные контрольные планы.

Очевидно, что пути не могут быть фиксированными, потому что в роутерах, каналах могут быть ошибки, и потому что сеть может быть очень большая. Их надо уметь пересчитывать.
Одно из решений - использовать платформу управления сетью, которая отслеживает статус сети и может пушить новые таблицы пересылок на роутеры, при обнаружении модификаций.  Это работает только если платформа имеет доступ ко всем роутерам. Это может потребовать отдельную сеть, которая позволяет платформе пушить информацию на таблицы пересылок. Openflow это протокол, который заставляет контроллеру сети устанавливать специальные вхождения в таблицу пересылок удаленных роутеров

Некоторые технологии обновляют таблицы пересылок в зависимости от того есть ли путь до сети пришедшего пакета. То есть пакет приходит, и роутер смотрит, есть ли у него запись сети этого пакета. Если нет, то он должен найти путь, и занести запись в таблицую
