## Domain Name System
Реальный DNS протокол запускается поверх как datagram сервиса, так и поверх битового потока. На практике datagram используется, когда нужно передать что то короткое, а byte-stream когда что то более длинное.
DNS сообщения состоят из - *Header - заголовок*, *Question* - запрос к DNS серверу, *Answer* - содержит ответ на вопрос(DNS сервер заполняет его), *Authority* - если DNS сервер не дал ответ, он дает доменные имена DNS сервером к которым можно обратиться,  дополнительная информация
На картинке структура заголовка - 12 байт.

| Название       | Зачем надо                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Transaction ID | 16битное рандомное значение, выбранное клиентом. Когда клиент посылает запрос на DNS сервер, он запоминает *вопрос* и его идентификатор. Когда сервер возвращает ответ, он возвращает ответ с TID выбранным клиентом. Так сопоставляется вопрос и ответ                                                                                                                                                                                                  |
| QR флаг        | Различать между ответом и запросом                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Opcode         | Различные запросы. Например стандартный запрос - клиент посылает имя - ему возвращаются данные. Может быть другой запрос - имя, затем данные чтобы сервер обновил у себя данные                                                                                                                                                                                                                                                                          |
| AA бит         | Устанавливается, когда у ответа есть авторитет на доменное имя, найденное в question секции. В DNS есть авторитетные\неавторитетные сервера. Авторитетные сервера всегда хранят самую новую информацию о домене. Неавторитетные не управляются владельцами домена - могут содержать неактуальную информацию. Например root не является авторитетным поскольку может просто не хранить эту информацию - он перенаправит на DNS сервер ниже в архитектуре. |
| RD бит         | устанавливается клиентом, когда он отправляет запрос к резолверу. DNS резолвер - устройство, на которое скидывается обход с верхних DNS серверов на нижние. Бит не ставится, например, при общении резолвера и рута                                                                                                                                                                                                                                      |
| RCODE          | различать ошибки                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| RA             | поддерживает ли сервер рекурсию                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Остальное      | Размер полей                                                                                                                                                                                                                                                                                                                                                                                                                                             |
Остальные 4 секции содержат *Resoursce Records* (RR). Каждая из них выглядит следующим образом.

| CLASS          | поддержка DNS в других сетях, помимо интернета                                                                                                                     |     |

| RDLength+RData | длина + сами данные, которые содержат информацию о типе, определенном в поле *Type*                                                                                |     |

#### Reverse DNS
Иногда нужно работать наоборот - из IP адреса получать имя. Это делается с использованием *PTR* (указатель). RData часть PTR RR содержит имя, а Name IP адрес, который обернут в in-addr.arpa домен. Например(11.2.0.192.in-addr.arpa).

Для того чтобы имена выглядели красиво, а не как порядок DNS серверов, используются CNAME *aliases*.
