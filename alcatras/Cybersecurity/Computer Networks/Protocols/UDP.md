UDP обеспечивает ненадежное connection-less соединение поверх ненадежного connectionless network уровня. Он не доставляет UDP, размер которых больше чем 65467 байт. О не гарантирует доставку SDU - могут быть потери. Он не доставит поврежденные SDU.

UDP нужен для того, чтобы позволить нескольким приложениям на 1 хосте обмениваться с несколькими приложениями на другом хосте. Приложение адресуется с помощью порта. Когда сервер использует UDP сервер регистрирует номер порта. Этот номер порта будет использоваться клиентом, чтобы общаться с сервером.

Всего может быть 65545 процессов, которые занимаю различные порты. Это числа никогда не достигается на практике. 
Порты разделяются на:
1. Привилегированные (1 < port < 1024). В большинстве UNIX-like OS только процессы, с root правами могут занимать эти порты. Сервера вроде DNS, NTP(Network Time Protocol), RPC(Remote Procedure Class). 
2. Ephemeral port - 49152 <= port <= 65535. Обычно клиенту не требуется какой-то специальный порт - просто выбирается из списка эфемерных портов
3. Registered port - 1024 <= port < 49152. Используется серверами.

Вычисление UDP чексуммы:
1. Заголовок с source адресом, адрес назначения, длина пакета, и 32 битное поле, содержащее 3 самых важных байта, установленных в 0 и low-order байты установленные в 17
2. Целый UDP сегмент, включая заголовок

UDP используется для приложений, где задержка должна быть минимальной или приложение само может восстановить пакеты.  Есть несколько типов:
1. Быстрый запрос - быстрый ответ. DNS, RPC, *Network File System - NFS* построена поверх RPC, и часто запускаются поверх UDP.
2. Компьютерные игры - минимизация задержки
3. Интерактивные VoIP.
