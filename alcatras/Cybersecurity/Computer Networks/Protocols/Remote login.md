#### SSH
Помимо шифрования современный ssh поддерживает передачу файлов, протокол туннелирования.
ssh работает поверх TCP.

Сначала обмениваются версиями протоколов и версиями программной реализации.
Далее используется SSH_MSG_KEX_INIT сообщение, который используется для того, чтобы договориться о криптографическом алгоритмов
ssh поддерживает 4 типа криптографических протоколов
1. Обмен ключами
2. Шифрование
3. Message Authentication Code (MAC)
4. compression
Сначала в SSH_MSG_KEX_INIT клиент отправляет свои 4 криптографических алгоритмах. Потом сервер принимает их, смотрит и что-то делает с ними(я так и не понял)
В результате мы получаем финальный список из 4 алгоритмов, которые будут использоваться в момент сессии.

После договоренности следует обмен ключами. Используются комбинации стандартных алгоритмов

1. Клиент генерирует рандомное число $a$ и посылает $A= g^a \mod p$.
2. Сервер генерирует рандомное число $b$ и вычисляет $B=g^b \mod p$, $K=b^a \mod p$ и подписывает своим приватным ключом. Реальное сообщение, которое отправится: $hash(V_{Client} || V_{Server} || KEX\_INIT_{Client} || KEX\_INIT_{Server} || Server_{pub} || A || B || K )$
3. Клиент после обычного DH может подтвердить ключ вычислив $K=A^b\mod p$ и подтвердить ключ

Есть несколько отличий от классического DH. Первое - необязательно наличие публичного ключа сервера. Если ключа нет в кэше, то ssh клиент выдаст предупреждение. Если ключ есть в кэше, но он поменян, то клиент выдаст более серьезную ошибку
Второе отличие - вычисляется хэш для всей важной информации. Это нужно чтобы предотвратить *downgrade* атаку
*Downgrade атака*
Атака при которой активный атакующий модифицирует сообщение таким образом, чтобы запросить использование более слабого алгоритма между клиентом и сервером. Например: клиент поддерживает 2 алгоритма, при этом 1 из них использует 128битный секретный ключ, а другой 48битный. Это иногда нужно для обратной совместимости. Пример:

1. Клиент отправляет открытый список поддерживаемых алгоритмов (например, `[AES-128, OldCipher-48]`) в сообщении `KEX_INIT_client`. Это сообщение передаётся в открытом виде, злоумышленник может его прочитать и изменить.
2. В хеш, который подписывает сервер, входит всё сообщение `KEX_INIT_client` целиком. То есть туда попадает именно тот список, который сервер получил.
3. Клиент видит что хэш не совпадает -> что то не так


***Использование ключей***
В современных реализация полученное $K$ не используется напрямую. Вместо этого используется хэш функция, с помощью которой вычисляется сразу 6 ключей.
1. Ключи для шифрования данных(для сервера и для пользователя)
2. Ключи для аутентификации данных(ключ для криптографической контрольной суммы)
3. Я не понял зачем он нужен(мб потом добавлю)

**Структура сообщений**
1. length - длина в байтах без MAC и самого поля
2. padding length количество байтов добавленных в конце
3. payload - данные
4. padding - рандомно добавленные данные в конце сообщения которые нужны, чтобы длина сообщения была кратна размеру блока алгоритма шифрования
5. MAC
#MAC
*MAC -Message Authentication code*
Вроде бы поле для инициализации ключей используется как раз-таки здесь.
Вычисляется, как $mac = MAC(key, sequence\_number || unencrypted\_message)$. Чтобы вычислить MAC нужно поддерживать счетчик.
Для реализации mac используется *HMAC*. Он работает с любой хэш функцией и ключом.  Ключ должен быть равен размеру блока.
HMAC использует ipad/opad которые представляют из себя строку из 20 байт 0x36/ox5c. HMAC вычисляется, как 
$H[K \oplus opad, H(K \oplus ipad, data) ]$. Ну и типо это мощнее

SSH поддерживает 2 механизма аутентификации, которая полагается на публичные ключи.
1. Хост дает серверу свои публичные ключи, чтобы условно зарегистрироваться. Дальше чтобы зайти хосту надо предоставить свой публичный ключ зашифрованный своим приватным. Сервер легко расшифрует. 
2.  Используется в сети где все друг другу доверяют. На каждом хосте есть пары пр_ключ/пб_ключ для всех *доверенных* пользователей. Когда ты хочешь подключиться к другому компу в сети, ты используешь ssh, вводишь пароль, далее ssh сам отправляет сообщение, подписанное приватным ключом, чтобы доказать другому устройству что ты это ты.
