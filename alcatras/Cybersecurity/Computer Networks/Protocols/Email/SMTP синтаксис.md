Далее диаграммы синтаксиса. Не то, чтобы это сильно важно было на самом деле, но пусть будет. 

| Правило      | Описание                                                                                                                                                                                            | Пример / Примечание                                   |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `ehlo`       | Команда приветствия (Extended Hello).                                                                                                                                                               | `EHLO client.example.com`                             |
| `mail`       | Команда для указания отправителя (Mail From).                                                                                                                                                       | `MAIL FROM:<alice@example.com>`                       |
| `rcpt`       | Команда для указания получателя (Recipient To). Может быть обычным почтовым ящиком, адресом `Postmaster` с доменом или без него.                                                                    | `RCPT TO:<bob@example.com>`<br>`RCPT TO:<Postmaster>` |
| `data`       | Команда, указывающая на начало передачи тела письма.                                                                                                                                                | `DATA`                                                |
| `quit`       | Команда завершения сессии.                                                                                                                                                                          | `QUIT`                                                |
| `Path`       | Определяет маршрут или адрес, заключенный в угловые скобки. По сути, это формат для `Mailbox`.                                                                                                      | `<alice@example.com>`                                 |
| `Domain`     | Определяет доменное имя, состоящее из основного `sub-domain` и ноля или более дополнительных поддоменов, разделенных точками.                                                                       | `example.com`<br>`mx.google.com`                      |
| `sub-domain` | Компонент домена. Начинается с буквы или цифры (`Let-dig`), после чего может следовать необязательная строка (`Ldh-str`), состоящая из букв, цифр или дефисов, и заканчивающаяся буквой или цифрой. | `example`<br>`my-server` (дефис внутри)               |
| `Let-dig`    | Базовый символ: буква (ALPHA) или цифра (DIGIT).                                                                                                                                                    | `a`, `Z`, `5`                                         |
| `Ldh-str`    | Необязательная строка из букв, цифр или дефисов, которая **обязательно** заканчивается буквой или цифрой (`Let-dig`).                                                                               | `-server1` (в составе `my-server1`)                   |
| `Mailbox`    | Полный почтовый адрес, состоящий из `Local-part`, символа `@` и `Domain`.                                                                                                                           | `user.name@example.com`                               |
| `Local-part` | Левая часть адреса (до @). Представляет собой "точечную строку" (`Dot-string`).                                                                                                                     | `john.doe`                                            |
| `Dot-string` | Последовательность из одного или нескольких `Atom`, разделенных точками.                                                                                                                            | `first.last`<br>`name`                                |
| `Atom`       | Одна или несколько единиц `atext` (печатаемые символы, допустимые в email-адресах, исключая спецсимволы вроде точки, скобок и т.д.).                                                                | `user`, `hello123` (без точек и спецсимволов)         |

| Правило | Описание | Пример / Примечание |
| :--- | :--- | :--- |
| **`Greeting`** | **Приветственное сообщение сервера.** Отправляется сразу после установки соединения. Состоит из кода `220`, пробела, домена (`Domain`) и опционального текстового сообщения (`textstring`) . | `220 smtp.example.com ESMTP Postfix` <br>`220 mx.google.com ESMTP ready` |
| **`textstring`** | **Текстовая строка**, состоящая из одного или более символов `atext`. Используется в приветствии и ответах для пояснения кода. | `ESMTP Postfix` <br>`Sender OK` <br>`Mailbox unavailable` |
| **`Reply-line`** | **Одна или несколько строк ответа сервера.** Может быть многострочным ответом: строки, кроме последней, содержат код и дефис (`-`), последняя строка — код и пробел (` `). Все строки заканчиваются `CRLF` . | `250-smtp.example.com Hello client`<br>`250-SIZE 37748736`<br>`250 HELP` |
| **`Reply-code`** | **Трехзначный числовой код ответа.** Первая цифра (2-5) определяет класс ответа, вторая (0-5) и третья (0-9) уточняют ситуацию . | `220`, `250`, `354`, `550` |

С помощью этих команд пользователь может общаться с сервером. Условно говоря, при подключении с telnet или netcat я буду писать эти команды для установления соединения, отправки emailов и так далее,
#кодывозврата 

```c
220  <domain> Service ready
221  <domain> Service closing transmission channel
250  Requested mail action okay, completed
354  Start mail input; end with <CRLF>.<CRLF>
421  <domain> Service not available, closing transmission channel
450  Requested mail action not taken: mailbox unavailable
452  Requested action not taken: insufficient system storage
500  Syntax error, command unrecognized
501  Syntax error in parameters or arguments
502  Command not implemented
503  Bad sequence of commands
550  Requested action not taken: mailbox unavailable
```
