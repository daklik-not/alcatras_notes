### Denial of Service attacks
Когда TCP сущность открывает TCP соединение, она создает **TCB - Transmission Control Block**. Он содержал текущее состояние TCP соединения - все переменные. Раньше у TCB был лимит на число соединений, которые могли находиться в SYN RCVD состоянии. При превышении лимита SYN Rcvd,  все полученные TCP SYN сегменты просто игнорировались.
Учитывая этот лимит, очень легко было сделать DoS атаку. Просто отправлять много запросов на установление соединения - сервер просто перестанет отвечать. Такая атака называется **SYN Flood**. Очевидно, что запросы будут посылать с разных IP.

Чтобы избежать таких атак, недавние TCP реализации не создают состояние TCP RCVD. В таком случае надо уметь опознавать SYN+ACK без сохранения *sequence* числа. Утверждается, что хранения состояние соединения очень много, и память забьется моментально.
Используются **SYN cookies***.
1.  Высокоуровневые биты содержат нижние биты медленно растущего счетчика
2. Хэш по local, remote IP адресу и портам, и секрету сервера.
Отличие в том, что теперь атака строится на CPU а не на память, что намного тяжелее.
SYN Cookie активируются только, когда ОС обнаруживает SYN flood атаку
#### Retransmitting the first SYN segment
Поскольку IP не гарантирует доставку.  Текущие TCP реализации запускают таймер ретрансмиссии. Таймер устанавливается на 3 секунды и увеличивается после каждой ретрансмиссии. TCP определяют максимальное число ретрансмиссий для каждого SYN сегмента.

***Optional Header Extensions***
#optional_header_extension 
1. MSS - Maximum Segment Size. Все TCP реализации должны получать сегменты, содержащие 536 байтов данных. Для больших используется TCP MSS. В TCB сохраняется MSS значение, которое использовал сервер/клиент. Может быть использовано только в сегментах, где установлен флаг SYN. Оно должно быть распознано всеми реализациями.
2. Включить расширения TCP. Можно, например, сделать более большие окна. Если клиент установил расширение, а сервер не установил, то расширение не применяется.\
3.  End of Option (0x00) — «стоп»: заполняет пустоту в конце заголовка для выравнивания по 32 битам.
4. No-Operation (0x01) — «прокладка»: используется между опциями для их выравнивания по 32-битным границам.
5. Остальные опции — имеют формат **TLV** (Type-Length-Value).
Они кодируются через *Type Legnth Value*: первый бит определяет type опции, второй бит определяет длину опции, оставшиеся байты специфичны. (3-5) Эти опции обеспечивают, что любая даже неизвестная опция будет прочитана.
