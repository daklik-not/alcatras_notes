
#### URI 
Четкая спецификация, особо смысла нет ее читать и разбирать но пусть будет.
```
URI           = scheme ":" "//" authority path [ "?" query ] [ "#" fragment ]
scheme        = ALPHA *( ALPHA / DIGIT / "+" / "-" / "." )
authority     = [ userinfo "@" ] host [ ":" port ]
query         = *( pchar / "/" / "?" )
fragment      = *( pchar / "/" / "?" )
pchar         = unreserved / pct-encoded / sub-delims / ":" / "@"
query         = *( pchar / "/" / "?" )
fragment      = *( pchar / "/" / "?" )
pct-encoded   = "%" HEXDIG HEXDIG
unreserved    = ALPHA / DIGIT / "-" / "." / "_" / "~"
reserved      = gen-delims / sub-delims
gen-delims    = ":" / "/" / "?" / "#" / "[" / "]" / "@"
sub-delims    = "!" / "$" / "&" / "'" / "(" / ")" / "*" / "+" / "," / ";" / "="
```

1. scheme - читай название протокола - http/https
2. authority - читай доменное имя/айпишник, если не дефолтный порт, то нужно явно его указать.
3. путь, хотя его тут нет
4. query - запрос, когда через ? передаем в uri какой то запрос
5. fragment - это как якорь в html, перекинет сразу на нужную часть документа.

### HTTP
Это текстовый протокол. Клиент посылает запрос - сервер отвечает. Работает поверх bytestream сервиса и слушает порт 80. Он был вдохновлен email протоколами.
**Запрос**
1. Метод, который показывает тип запроса, URI и версию http протокола

   2. Заголовок, который используется клиентом, для определения опциональных параметров запроса.
   3. опциональный MIME документ.
   
**Ответ**
1. Линия статуса, который показывает, был ли успешен запрос.
2. Заголовок с доп-инфой об ответе.
3. MIME документ

### HTTP Methods
Есть 3 главных метода
1. GET
Он используется, чтобы получить документ с сервера.
Клиент должен установить TCP соединение на 80 порту и послать что-то подобное

```c
GET /MarkUp/ HTTP/1.0 // получит [http://www.w3.org/MarkUp/]
```

2. HEAD - вариация метода GET, которая позволяет получать только заголовки для заданного URI.
3. POST используется, чтобы послать документ на сервер. Документ связан с HTTP запросом, как MIME документ
4. PUT -  используется для загрузки или полного обновления существующего документа на сервере по конкретному адресу (URI).
5. PATCH - Используется для **частичного изменения** документа на сервере.
6. DELETE - Используется для удаления указанного ресурса (документа или файла) с сервера.
7. OPTIONS -  Используется для определения параметров связи и поддерживаемых сервером технологий для конкретного ресурса. Короче все что связано с доступом. Через заголовок OPTIONS посылаются preflight запросы. 
8. CONNECT - Используется для установления сетевого туннеля с сервером (обычно через прокси-сервер).
*Главные заголовки*
9. *Content-Length* - длина MIME документа в байтах
10. *Content-type* - тип контента, например text/html для html страниц
11. *Content-Encoding* - кодировка MIME документа.

*Специфичные для ответов*
1. *Server* - показывает версию веб-сервера, который сгенерировал ответ, иногда отключается
2. *Date* - дата и время ответа
3. *Last-Modified* - последнее время модификации документа

*Специфичные для запроса*
1. *User-Agent* - информация о клиенте, который сгенерировал http запрос. Чаще всего браузер
2. *Referrer* - показывает URI документа, который клиент посещал перед отправлением http запроса. Полезно при рекламе
3. Host содержит полное доменное имя запрашиваемого URI. Пример использования: web.example.com/index www.example.net/index. Для них http запрос будет выглядеть примерно вот так:  GET /index.html HTTP/1.0. Без них это невозможно
4. Vary  - это заголовок ответа, который содержит заголовки запроса, которые повлияли на содержимое ответа

*Кода возвратов*
Помимо того, что есть в #кодывозврата
200OK - запрос был обработан сервером и ответ валидный.
301 Moved Permamently - запрашиваемый документ больше не доступен на сервере.
304 Not Modified - версия документа на сервере не новее чем кэшированная у клиента.
400 -  ошибка в синтаксисе.
404 Not Found - документа не существует.
500 - сервер не может обработать запрос на своей стороне.

*TCP control*
Изначально TCP соединение устанавливалось на каждый http запрос - поскольку как правило люди запрашивали текст, а затем читали его, смысла в постоянном tcp было не очень много.
Потом были придуманы сохраняющиеся(persistent) TCP соединения - по нему можно отправлять несколько tcp запросов.
Есть несколько заголовков для регулировки
1. *Connection* - Keep-Alive - не закрывать, Close - закрывать
```c
Connection: Keep-Alive
```
1. *Keep-Alive* - используется серверами, чтобы информировать клиента о том на каких условиях он соглашается на постоянное соединение. Типичный запрос содержит максимальное число запросов, которое обслужит сервер на текущем tcp соединении и timeout после которого сервер закроет соединение.
```c
Keep-Alive: timeout=15, max=100
```

Важно, что HTTP запросы не должны привязываться к TCP соединения, каждый должен содержать всю нужную информацию.
Тем не менее иногда хочется возвращать для http запросов от определенных пользователей определенную информацию.

1. Аутентификация. Раньше user:pass было в URI. Сейчас в заголовках. Тем не менее запоминать и вводить пароль для каждого сервера не очень приятно
2. Иногда можно написать в специальный *Accept* заголовки, например *Accept-Language*
3. *Cookies*. Короткая строка, которая выбирается сервером, чтобы представить заданного клиента. Есть header *Cookie* и *Set-Cookie*. Set-Cookie содержит несколько дополнительных параметров, включая доменное имя для которого cookie валиден. Клиент сохраняет cookie на диске и при каждом запросе отправляет *Cookie* заголовок, который содержит cookie. Ответ сервера в таком случае это функция от url и cookie.
