Устанавливается с помощью трехстороннего рукопожатия - **three-way-handshake**
 Когда клиент хочет открыть соединение с сервером, он создает TCP сегмент с:
**SYN сегмент**
2. SYN флаг установлен
3.  *Sequence* число - значение счетчика клиента

Сервер отвечает
**SYN-ACK сегмент**
5. SYN флаг
6. *Sequence* число - значение счетчика сервера
7. ACK флаг
8. *Acknwoledgment* устанавливается в полученное $sequence number$ + 1$\mod 2^{32}$.

Клиент отвечает
1. ACK флаг
2. acknowledgment число установленное в  $sequence number + 2 \mod32$

После этого TCP соединение открывается

***Вычисление изначального sequence числа***
Нужно рандомизировать и усложнить создание изначального числа - **ISN**. Представим ситуацию - сервер доверяет IP хоста и позволяет ему авторизоваться без пароля. Тогда злоумышленник может послать пакет, который содержит  source IP доверенного хоста. После этого, через короткий промежуток времени он может послать опознавание - после чего откроется соединение и он сможет посылать команды серверу, как админ. Это возможно, если он угадает ISN. Современная формула ISN
$$ ISN = M + H(localhost, localport, remotehost, remoteport, secret).$$
где $M$ это текущее значение часов.
___

Очевидно, сервер может отказать открыть соединение. 
Причины: нет процесса, который слушает порт, к которому хочет обратиться клиент, недостаток ресурсов, безопасности и так далее. В таком случае сервер посылает **RST** - немедленный разрыв соединения.
