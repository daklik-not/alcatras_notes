### Exchanging data over a QUIC connection
QUIC использует потоки. Поток это просто последовательность байт.
Когда сервер создает поток, первые 2 бита идентификатора(01,11) - двухсторонни и односторонний
Когда клиент создает поток первые 2 бита идентификатора(00,10) - аналогично
Потоки создаются неявно - просто посылаем с нужным идентификатором данные. 
QUIC помещает все данные внутри специальных фреймов *STREAM*

```
STREAM Frame {
   Type (i) = 0x08..0x0f, //тип
   Stream ID (i),//идентификатор
   Offset (i),//позиция первого байта данных потока в bytestream
   Length (i),
   Stream Data (..),
}
```

Самый низкий порядковый бит поля *Type* ведет себя как FIN бит. Когда он равен 0 - последующие данные шлются по этому потоку. Когда он равен 1 -  Stream кадр содержит последний байт, посланный по данному потоку. Поток закрывается, как только последний бит потока был доставлен пользовательскому приложению

```c
STREAM Frame {
   Type (i) = 0x0e,
   Stream ID = 1,
   Offset = 0
   Length = 2
   Stream Data = AB
}
				STREAM Frame {
					Type (i) = 0x0e,
					Stream ID = 5,
					Offset = 0
					Length = 1
					Stream Data = 1
				}
				
STREAM Frame {
   Type (i) = 0x0e,
   Stream ID = 1,
   Offset = 2
   Length = 1
   Stream Data = C
}
				STREAM Frame {
				   Type (i) = 0x0f,   /* FIN bit is set, end of stream */
				   Stream ID = 5,
				   Offset = 1
				   Length = 2
				   Stream Data = 23
				}
				
STREAM Frame {
   Type (i) = 0x0e,
   Stream ID = 1,
   Offset = 3
   Length = 4
   Stream Data = DEFG
}
```
С помощью FIN мы закрываем *gracefully*
Можно с помощью *Reset_Stream* - просто отправитель посылает это и данные по потоку больше не принимаются
Или получатель отправляет *Stop_Sending* - ему отвечают *Reset_Stream*

#### Flow control in QUIC
Нужно контролировать количество передаваемых данных, пакетов

*Connection-level flow control*
Можно установить максимальное количество байт, которое будет передано по текущему соединению - *initial_max_data*.  Получатель может увеличить максимальное количество через *MAX_DATA*. Если лимит все-таки достигнут, хост должен послать DATA_BLOCKED кадр.
![[Pasted image 20260605163954.png]]
Во время рукопожатия получатель указывает максимально число потоков - 
*initial_max_streams_bidi*, *initial_max_streams_uni*. Можно увеличить *MAX_STREAMS*

*Stream-level flow control*
Во время рукопожатия можно задавать параметры ограничения для максимального количества байт на каждом потоке. Эти лимиты можно обновить, если послать *MAX_STREAM_DATA* кадры. Здесь аналогично для *Stream_Data_Blocked*

Как видно с картинки выше, соединение не должно пустовать - хост, превзошедший лимит просто будет посылать DATA_BLOCKED. 
Чаще всего вместе с QUIC используют фиксированный размер буфера - Static Flow Control. Есть еще auto-tuning, как в TCP,  но он мало используется в QUICK реализациях
