Потоки полностью реализованы в пользовательском пространстве и управляются без участия ядра. Потоки реализуются библиотекой. При таком подходе потоки управляются runtime системой, которая представляет из себя набор процедур с помощью которых она управляет потоками. Каждому процессу нужна своя **threadx table** - аналог process table. Она знает только о том, что относится к потоку - программный счетчик, указатель на стек, регистры, состояние и тд. Если происходит **thread switch** -  смена потока, то в таком случае все операции такие как - блокировка текущего, сохранение его состояния и тд делает как раз таки runtime система. **Thread switch** реализуются с помощью thread_yield. У каждого процесса может быть свой алгоритм планирования

Есть и минусы. Главный из них - когда надо заблокировать поток, ОС не знает про существование отдельного потока, поэтому она блокирует все потоки, то есть весь процесс. Это очень неэффективно. Эту проблему можно попытаться решить с помощью неблокирующих системных вызовов, но это требует переписывания кода ОС, что очень плохая практика. Также можно переписать код не самой ОС, а библиотеки системных вызовов, следующим образом - будет выполняться вызов select(), который говорит о том, заблокируется ли процесс или нет. Если нет, то поток либо заблокируется, либо будет висеть в постоянном ожидании, пока select не скажет, что данные готов. Код написанный вокруг системного вызова называется **wrapper**
Вторая проблема - реализация мультипоточности. В пользовательской среде впринципе нет такого понятия, как прерывания. Каждый поток должен добровольно отдавать данные другому потоку -> если не отдаст, весь процесс встанет.
Третья проблема - потоки чаще всего используются на загружённых серверах, где потоки постоянно блокируются, потому, что например считывают данные, затем обрабатывают их, затем отправляют обратно. Если потоку нужно будет заблокироваться - заблокирован будет весь процесс.
```
// Псевдокод - обертка для неблокирующего I/O
int non_blocking_read(int fd, void *buf, size_t count) {
    // Шаг 1: Проверить, будет ли read блокировать
    if (select(fd, READ_CHECK) == WOULD_BLOCK) {
        return WOULD_BLOCK;  // Не вызывать системный вызов
    }
    
    // Шаг 2: Если безопасно - выполнить read
    return read(fd, buf, count);
}

// Использование в потоке
void* thread_function(void* arg) {
    char buffer[MAX_SIZE];
    while (true) {
        // Попытка чтения через обертку
        int result = non_blocking_read(fd, buffer, sizeof(buffer));
        if (result == WOULD_BLOCK) {
            // Передать управление другому потоку
            yield();
            continue;
        }
        if (result > 0) {
            // Обработать данные
            process_data(buffer, result);
        }
    }
}
```
PS: в современных ОС чаще всего используются потоки ядра. Однако это не значит, что пользовательские потоки бесполезны. Они используются, только не операционными системами, а runtime системами, например в Go/
