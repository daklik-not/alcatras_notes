**Semaphores**
Чуть позднее Дийкстрой были предложен новый тип данных - **semaphores(семафоры)**. С ними можно было делать 2 операции - *up() и down()*
Фактически семафор хранит количество wakeup битов. При вызове down() - если семафор > 0, то процесс просто завершает down(). Если семафор равен 0 - процесс отправляется спать не завершив down().  Операция up() в свою очередь выбирает какой-то процесс и будит его, позволяя завершить down(). Основная идея семафоров в том, что не атомарные. То есть непрерывные -> пока выполняется down() не может произойти прерывание  -> не возникает race condition. Список спящих процессов является составляющей самой структуры семафора: 
```
struct semaphore {
    int value;              // Текущее значение счетчика семафора
    struct process *queue;  // Указатель на очередь (список) процессов, ожидающих этот семафор
};
```
Вопрос атомарности решается благодаря использования таких инструкци как TSL или XCHG.
 Есть специальный тип семафоров, который называется **binary semaphores**. Они принимают значение 0 или 1. Их используют для ограничения вхождения в критический регионе.
 В системах использующих семафоры, нормальным способом спрятать прерывания является использование семафора, установленного на 0 для каждого I/O устройства.  Сразу после запуска девайса управляющий процесс выполняет down() на связанном семафоре. Когда приходит прерывание, обработчик прерываний затем делает up() на связанном семафоре. Это нужно, чтобы планировщик мог запустить **device manager(хз пока что это)**.
