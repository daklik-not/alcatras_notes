Проблема инверсии приоритета. Ее суть в том, что поток низкого приорета не может выполняться.

**Пример из заметки про busy-waiting**
Рассмотрим ситуацию - один процесс с низким приоритетом, другой с высоким. Низкий находится в критической секции, происходит прерывание, теперь высокий хочет зайти в критическую секцию. Он не может зайти в нее, поскольку низкий в критическом сегменте, а низкий не может выйти, потому, что он не может запуститься, пока запущен высокий. Это называется -- **priority inversion problem**

**Пример priority inversion c мьютексом**
Рассмотрим пример из книги - ровер на Марсе
Радиопередачи отвечающие за поиск пути, перестали присылать данные постоянно, требуя сброса системы снова и снова. Выяснилось, что 3 потока мешали друг другу.
Pathfinder использовал форму разделяемой памяти, которая называлась **information bus**, для передачи информации между его различными компонентами. Низкоприоритетный поток периодически использовал эту шину для того, чтобы передать метеорологические данные. Доступ к шине управлялся мьютексов в коде ровера. Третий поток отвечал за коммуникации - ему не нужны были мьютексы.  Проблема инверсии потока возникала, когда средний поток вытеснял низкий с уже захваченным мьютексом. В таком случае высокий поток просто блокировался во время выполнения среднего процесса, который работал достаточно продолжительное время.

**Способы решения**
1. **Priority ceiling(потолок приоритета)** - свяжем приоритет с мьютексом. Просто дадим потоку с мьютексом самый высокий приоритет. Тогда наша проблема не возникнет. То есть заранее назначает высокий приоритет не потоку, а _мьютексу_
2. **Priority inheritance(наследование приоритета)** - низкоуровневая задача, которая держит мьютекс будет наследовать высокий приоритет другой задачи.
3. **Random boosting** - используется в Windows. Рандомно выбирает поток, который держит мьютекс, дает ему высокий приоритет до того момента пока он не выйдет из критического сегмента. Оно неплохо решает и проблему с busy-waiting
Все решения обьединяет одно - потоку с мьютексом надо дать высокий приоритет
