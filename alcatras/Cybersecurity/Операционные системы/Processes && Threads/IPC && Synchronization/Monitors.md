При ручном использовании мьютексов и условных переменных надо быть очень осторожным. Любая неправильная точка кода может привести к deadlockу - взаимной блокировке и полной остановке программы.
Для решения этой проблемы придумали **monitor**. Монитор это набор процедур, переменных и структур данных сгруппированных в специальный модуль или пакет.
Монитор - концепция языка. Грубо говоря, компилятор будет обрабатывать мониторный код специальным образом. Именно поэтому нельзя написать код монитора на C - в этом языке просто нет такой концепции.
Компилятор обрабатывает мониторы таким образом, что только 1 процесс может быть в мониторе в 1 момент времени. Обычно для реализации мониторов используются мьютексы или бинарные семафоры.
Очевидно, такой подход разительно повышает безопасность.
Однако мониторы не дают возможности блокироваться, когда процесс не может продолжиться. Для этого используются условные переменные. В их заметке написано как они работают. Если сигнал сделан на условной переменной, на которой ждут несколько процессов, только один из них, определяемый системным планировщиком остается.

Мониторы используются в Java. Если добавить слово $synchronized$ к обьявлению методу, то Java гарантирует, что как только поток начал выполнять synchronized метод, никакой другой поток не сможет выполнить synchronized метод этого обьекта.
Synchronized методы отличаются от классических мониторов разительным образом - у Java нет встроенных condition variables. Вместо них предлагаются процедуры - **wait** и **notify**. Если они используются внутри синхронизированного метода, то они не являются объектами race condition.  Теоретически wait может быть прерван, однако он оборачивается вот в такую штуку: 
```c
private void goToSleep() {
    try {
        wait();
    } catch (InterruptedException exc) {
        // игнорируем прерывание
    }
}
```

Однако у мониторов есть существенные недостатки. Для того чтобы писать операционные системы используя мониторы, нужен язык, который имеет их встроенную поддержку. Очевидно, что на Java ОС не пишут. Другая проблема - они не работают на дистрибутивных системах. Что важно ни одна из примитивов вроде мьютексов, семафоров, системных вызовов не работает на них.
