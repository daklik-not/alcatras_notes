
**Process Creation**'
Есть 4 причины, по которой могут быть созданы процессы
1. Инициализация системы
2. Выполнение fork() или createProcess()
3. Пользовательский запрос на создание процесса
4. Пакетная работа

 1)При запуске операционной системы обычно создается некоторые количество процессов. Например, процессы которые работают фоном и ждут, чтобы обработать какую-то активность - процессы демоны(**daemons**) .

2)Используется, когда задача процесса легко может быть разбита с другим процессом.
Например - считывание данных - один процесс читает данные и записывает их на буфер. Другой убирает данные с буфера и что-то делает с ними.

3)Просто пользователю нужно создать процесс. Например двойное нажатие на ярлык приложения создает процесс приложения.

4)Пакетная работа(**batch job)**. Это работает так - процесс выполняет большое количество действий подряд без интерактивного вмешательство пользователя. Например мэйнфрейм банка подсчитывает прибыль или что-то вроде того

Все процессы создаются путем того, что другой процесс вызывает системный вызов. Один процесс существует изначально - в Linux он называется **init**. **fork** - создание процесса, **execve** - выполнение программы. В Windowns  - **CreateProcess** - параметры выполненения указываются сразу же.

После создания процессов у них раздельное адресное пространство. При создании дочернего процесса обычно копируется адресное пространство родителя.  Используется **copy-on-write**. Фактически до первого изменения у них одно адресное пространство, после первого изменения уже раздельное.

**Process Termintaion**
Есть 4 способа, которыми процессы могут завершиться.
1. Нормальный выход(добровольный)
2. Выход с ошибкой(добровольный)
3. Фатальная ошибка(недобровольная)
4. Убит другим процессом.

Если процесс завершается нормально, то просто выполняется системный вызов **exit**. 
Если в процессе происходит ошибка, чаще всего вызванная багом. Процесс может сказать операционной системе, что он хочет обработать ошибку сам, вместо завершения. Такие ошибки возникают например от деления на 0 или обращения к несуществующей памяти
Если в процессе происходит фатальная ошибка, например, процесс пытается считать данные из несуществующего файла, то процесс аварийно завершается.
Процесс убивает другой процесс(TerminateProcess - kill). В основном используются сигналы - например **Segkill**.
