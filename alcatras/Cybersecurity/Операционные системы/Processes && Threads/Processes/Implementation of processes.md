**Implementation of Processes**
Для реализации модели процессов операционная система реализует таблицу, которая называется **process table**. Каждое ее вхождение называется  **PCB** - **Process Control block**.
В этой таблице хранится важная информация  - информацию о состоянии процесса, включая program counter, stack pointer, адресного пространства процессов файловые дескрипторы и информация для планирования процессов. Эта информация используется для сохранения информации при смене контекста. На рисунке показано, что примерно хранится в этой таблице

Сначала происходит прерывание. Процессор автоматически сохраняет минимальный набор контекста текущего выполняемого процесса - программный счетчик(program counter), и состояние процессора (program status word) на стек ядра процесса. Затем процессор использует специальный аппаратных механизм - вектор прерываний, который представляет собой таблицу адресов в фиксированной области памяти, где для каждого типа прерывания записан надлежащий адрес процедуры обслуживания прерывания - **ISR - Interrupt Service Routine**. Начальная часть ISR, написанная на ассемблере, немедленно сохраняет полное состояние всех регистров общего назначения и других критических регистров процесса в предварительно выделенную область ядерного стека прерванного процесса. Это дает возможность восстановления. После этого ISR инициирует выполнение высокоуровневого кода на C, который специфичен для каждого типа прерывания. Если в результате обработки планировщик принимает решение о необходимости переключения контекста, то происходит полное сохранение информации процесса на PCB. А именно в PCB хранится указатель на ядерный стек процесса. Затем планировщик загружает состояние процесса из его собственного PCB. При смене контекста указатель стека **Stack pointer**. загружается в регистр SP процессора.
