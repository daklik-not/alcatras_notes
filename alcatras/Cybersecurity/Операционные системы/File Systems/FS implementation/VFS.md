#### Virtual File Systems
Windows понимает, какая ФС используется по букве диска. В Linux поддиректории могут иметь свои файловые системы. Тем не менее для пользователя разницы никакой нет.
Присутствие множества ФС отражалось на реализации, поэтому придумали концепт **VFS -Virtual FS**. Ключевая идея - абстрагировать ту часть ФС, которая общая для всех ФС и поместить этот код в специальный слой, который будет вызывать фундаментальные ФС для управлением данными. У VFS есть общий верхний интерфейс для пользовательских процессов  - POSIX Interface. Так же есть нижний интерфейс для конкретных файловых систем. Создатели ФС должны были обеспечить поддержку функций, через которые VFS вызывало их.

Изначальная задача VFS - поддержка удаленных ФС, используя **NFS - Network FS** протокол. Пока FS поддерживает функции VFS,  ей неважно как работает FS.
У VFS есть несколько ключевых объектов - супер блок(описание ФС), v-node(описание файла), директория(директория). У каждого типа объекта были несколько связанных с ними операций, которые FS должна поддерживать. Также у нее есть таблица монтирования(про ФС и куда они подключены) и массив файловых дескрипторов.
Корневой файл регистрируется с помощью VFS. Подключаемые ФС должны предоставить список адресов функций, который требует VFS - например в виде таблички. Потом они просто через эту таблицу вызываются при работе с ФС.  ФС обнаруживается с помощью супер блока. Чтобы не вдаваться в подробности реализации скажу, что фактически на уровне VFS все то же самое, что и в обычных ФС, с одним условием, что вместо вызова операции записи на диск мы вызываем функцию другой ФС с записью на диск.
