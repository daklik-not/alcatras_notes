### Implementing Directories
Перед тем, как читать файл, он должен быть открыт. При открытии файла ОС использует название пути, предоставленное пользователем, чтобы определить файл директории. В нем ОС находит информацию, нужную, чтобы найти блоки диска. В современных ОС там чаще всего хранится номер i-node.
Один из вопросов - где нужно хранить атрибуты. Каждая ФС реализует различные типы атрибутов. Можно хранить их напрямую в папке директории. В системах, использующие i-node атрибуты хранятся в i-node - то есть в kernel памяти. Тогда в файле директории должно храниться только i-node и название файла.

В программке, которая в папке с директориями, в структуру dirent хранится не только i_node. То есть там структура name - dirent. Тем не менее то, что содержит dirent помимо i-node касается скорее перемещению по файлу директории, нежели чем работе с файлом.
___
Есть проблема с длинными именами файлов. Если поставить просто большой фиксированный размер, то эти файлы будут съедать много памяти.
**Первый подход**- есть фиксированный заголовок, который содержит фиксированные данные - владелец, время создания, защитную информацию и другие атрибуты. После этого следует реальное имя файла, неважно какой длины. Оно заканчивается на специальный символ. Длина имени файла дополняется до длины кратной длине машинного слова - для оптимизации. У такого подхода есть минусы - когда файл убирается, то остается дырка неизвестного размера и не факт, что следующий файл в нее влезет. Другая проблема - одно вхождение директории занимает несколько страниц - приводит к страничному промаху
**Второй подход** - храним указатель на имя, которое лежит в куче, после него данные. Тогда вхождение в директорию фиксированного размера, любой файл влезет + в куче не надо дополнять имя файла до длины кратной длине машинного слова.
___
Утверждается, что в куче выравнивание делается уже при выделении динамической памяти.
___
Обычно файл в директории ищется линейно. Для очень больших директорий имеет смысл использовать хэш-таблицу. В хэш таблицу по ключу имени помещаем указатель на вхождение файла. Если происходит коллизия - строится linked list в этой ячейке. При чтении файла проверяются все имена файла в цепочке, пока не найдется равное.
Такой подход ускоряет поиск, но усложняет администрацию
Можно кэшировать, но это работает только если есть ''рабочий набор'' файлов.
