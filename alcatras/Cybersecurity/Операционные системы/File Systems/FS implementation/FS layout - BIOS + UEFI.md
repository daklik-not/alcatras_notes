Файловые системы хранятся на диске. Большинство дисков могут быть разделены на 1 или более частей, с независимой файловой системой на каждой части.

#### Master Boot Record - BIOS
На старых системах сектор 0 диска назывался **MBR (Master Boot Record)** и использовался для запуска компьютера. Конец MBR содержал partition table. Эта таблица давала начальные и конечные адреса каждого раздела. Одна из частей в таблице помечалась, как активная.
Когда компьютер запускался BIOS считывала данные и выполняла MBR. Сначала программа MBR определяла активный раздел, читала его первый блок, который назывался **boot block** и выполняла его. Программа в boot блоки загружала ОС, сохраненную в этой части. Для единообразия каждый раздел начинался с boot блока, даже если в нем не было ОС.

#### UEFI - GPT
Прошлый способ медленный, архитектурно зависимый, и ограничен маленькими дисками. Intel предложили иной подход - **UEFI - (Unified Extensible Firmware Interface)**. UEFI смотрит расположение **partition table**  во втором блоке устройства. Он резервирует первый блок, как специальный маркер для ПО, который ждет MBR - здесь его нет. **GPT - (GUID Partition Table)**  - содержит информацию о расположении различных разделов на диске. UEFI сохраняет бэкапы GPT на последнем блоке. Как только GPT найден, firmware - микропрограммы, имеют достаточно функциональности, чтобы читать файловые системы различного типа. Согласно стандарту UEFI firmware должно поддерживать хотя бы файловые системы типа FAT.  Одна такая файловая система помещается на специальный раздел диска, известный как EFI раздел(у меня на компе он есть кстати).  Это специальный раздел FAT32, где хранятся только загрузчики ОС (.efi-файлы), драйверы для самой загрузки и **конфиги**

**Своими словами**
Сначала запускается UEFI, потом UEFI читает bootloader с флешки, отформатированной в FAT32, загружает его в память. Далее bootloader передает управление установщику. Потом я выбираю на какой диск буду ставить ОС, и установщик размечает диск, создает GPT, создает EFI - отформатированный в FAT32, после чего bootloader запускает главную программу установки ОС, которая будет работать уже с нормальной файловой системой.
