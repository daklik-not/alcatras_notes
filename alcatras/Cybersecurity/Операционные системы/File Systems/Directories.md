### Directories
Директории  - те же файлы. Они нужны для отслеживания файлов.
#### Single-Level Directory Systems
Одна папка - **root**. Такой подход был на первых персональных компьютерах. Плюсы - быстро определять положение файла. Такой подход иногда используется на некоторых embedded системах. На обычных системах вроде Windows и Linux он устарел
#### Hierarchical Directory Systems
Позднее появилась необходимость в группировку файлов. Часто используется подход, когда у пользователя есть своя приватная директория, все поддиректории которой принадлежат пользователю. Так организованы все современные файловые системы. Впервые такой подход использовался MULTICS.

#### Path Names
Нужно уметь искать файлы в директориях при иерархичном подходе. 
**Absolute path**  - путь от корневой папки. Полезно для библиотек процедур, когда непонятно, откуда процесс ее вызовет.
**Relative path** -  путь от рабочей директории. Спуск по директориям достаточно медленная операция. Если нужно читать много файлов, то лучше поменять рабочую директорию процесса на директорию с файлами.
У каждого процесса есть своя рабочая директория. Рабочую директорию процесса можно поменять по мере выполнения программы. Библиотека процедур не должна менять рабочую директорию, по крайней мере, должна вернуть ее назад.
Часто на системах - 
```..``` - ссылка на предыдущую директорию в дереве.
```.``` - ссылка на текущую директорию
