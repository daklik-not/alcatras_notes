#### Keeping Track of Free Blocks
Нужно отслеживать адреса свободных блоков.
1) Будем использовать линкед лист  блоков диска, где каждый блок будет хранить максимально возможное количество номеров блока диска. Если свободные блоки часто приходят последовательно, то можно дополнительно хранить число count, которое будет показывать сколько блоков пришло. Но при высокой загруженности это создает дополнительную нагрузку. В RAM нужно хранить только 1 блок *списка свободных блоков*.
   Когда файл удаляется его номера блоков записываются в блок, который в RAM. Если этот блок заполнен он записывается на диск. Важно подметить, что когда файл создается, порядок выглядит примерно так - 1) читаем номер блоков из *блока списка свободных блоков*  - 2) инициализируем write() на диск. Эти 2 операции повторяются пока файл не будет записан. Есть проблема - когда блок указателей практически пустой, то при определенных условиях, например последовательности небольших временных файлов это может вызвать лишние записи/чтения диска.   Надо стараться поддерживать состояние, когда большинство блоков с номерами на диске полные, но тот который в памяти полу полный. Когда блок в памяти заполняется, он записывается на диск, и из памяти читается полу полный блок. Если в памяти всегда полупустой блок, то он всегда может без обращения к диску удовлетворить запись/чтение небольших временных файлов. Это будет решать проблему

2)В битовой карте каждому дисковому блоку соответствует один бит. При значении 1 блок свободен, при 0 — занят. Битовая карта хранится на диске блоками; в памяти может находиться один или несколько блоков bitmap.
Преимущество метода состоит в том, что при последовательном сканировании bitmap аллокация происходит из одного диапазона, что приводит к размещению файлов в соседних физических блоках и уменьшает движения disk arm.
