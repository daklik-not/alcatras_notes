#### Disk Space Management
Есть 2 подхода для выделения памяти для n байт: можно просто выделить n последовательных байт в памяти, а можно разбить эти байты на непрерывные блоки. Первый подход плох тем, что если файл растет и упирается в другую память, его надо переносить куда-то в диске - это дорого. Поэтому почти все современные ФС разбивают файл на блоки, которые не должны быть смежными.
#### Block Size
Размер блока также важная проблема. Для HDD лучше использовать размер сектора, трека или цилиндра. В SSD лучше использовать размер flash страницы. Если используется paging - использовать размер виртуальной страницы. Если блок большой - то даже очень маленькие файлы будут занимать целый блок. Если блок маленький, то большинство файлов распределится по множеству блоков, что очевидно уменьшает производительность.  Этот конфликт неразрешим. График показывает зависимость при 4КБ среднем размере файла. Обычный компромисс - 4КБ. На SSD waste возникает на уровне флэш-блока и на уровне флеш-страницы для файлов соответствующего размера.
