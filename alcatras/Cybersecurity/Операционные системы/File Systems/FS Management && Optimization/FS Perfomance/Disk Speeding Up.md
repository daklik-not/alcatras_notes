#### Block read Ahead
 Можно использовать аналог prepaging для блоков. Поскольку файлы читаются последовательно, то если ФС прочитала блок k, она может сделать предположение, что ей понадобится также блок k + 1. Чтобы отличить файлы, которые нужно читать последовательно она может попытаться считать паттерн обращений к файлу.
#### Reducing Disk-Arm motion
Чтобы сократить количество движений руки HDD блоки, к которым ФС будет обращаться последовательно лучше располагать на 1 цилиндре. Когда файл создается/пишется ФС должна выделить блоки, которые близко друг к другу - идеально подходит битовая карта, а не ССБ.
Можно кластеризовать блоки - выделять для файла память не по 1 блоку, а по 2. Тогда количество поисков уменьшается вдвое.
Также для ускорения работы HDD может хранить логически последовательные блоки физически рядом - на 1 цилиндре или близко друг к другу.
Для каждого файла нужно прочитать инод, затем сам файл. Обычно иноды располагаются в начале диска. Чтобы ускорить это можно поместить иноды в середину, или сгруппировать иноды, блоки и свободные листы.
Насколько я понял, это будет работать только в том случае, если логические адреса ФС находятся логически рядом. Если логические адреса связаны с диском HDD рандомно, то это не будет работать.
