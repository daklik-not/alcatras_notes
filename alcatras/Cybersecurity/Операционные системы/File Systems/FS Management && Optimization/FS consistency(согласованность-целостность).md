#### FS consistency(согласованность/целостность)
После краша ФС может находится в несогласованном состоянии. Особенно если несохраненные блоки - блоки структур ядра. Большинство компьютеров используют утилиту для проверки согласованности ФС - UNIX- *fsck*, Windows - *sfc*. Утилита может запускаться при каждом запуске системы.
```c
Команда cmd:
sfc /SCANNOW - Проверка целостности всех защищенных системных файлов и восстановление, по возможности проблемных файлов
```
Описание работы *fsck*
Все чекеры проверяют каждый файл системы независимо от других. Журналируемые файловые системы  не нуждаются в запуске чекера - они решают большинство проблем самостоятельно. 
**Block consistency**
Программа строит 2 таблицы, каждая содержит счетчик для каждого блока. Счетчики в первой таблице отслеживают как часто каждый блок входит в файл. Счетчики во второй таблицы, как часто блок блок бывает в списке сб/битовой карте сб. 
Затем программа читает все иноды минуя ФС. Теперь можно построить список всех номеров блоков, использующихся в соответствующих файлах. Теперь мы можем заполнить первую таблицу прочитав блоки от инодов. Далее программа делает тоже самое для списка сб и второй таблицы.
Если все корректно, то значения в i ячейке должны быть противоположными. Это рисунок (a).
Если оба значения равны 0 - рисунок (b), то блок просто добавляется в список свободных блоков. Блок 2 здесь - **missing block**. 1-1 ситуация не возникает из-за устройства ФС.

**Directory consistency**
Cначала бегаем по файлам директорий - смотрим сколько каждый файл входит в каталоги.  Учитываем хард-линки. Потом сравниваем это с количеством ссылок на файл в иноде файла.
Если счетчик ссылок слишком высокий/слишком низкий- устанавливаем корректный счетчик ссылок в иноде. При этом если счетчик слишком низкий есть вероятность, что вхождения в директорию будут указывать на чужие файлы, что может привести к перезаписи чужих данных.
Обычно проверка блоков и директорий делается вместе. Есть другие проверки, например, если номер инодов больше числа всех инодов, странные разрешения, файлы, расположенные в пользовательских директориях, но которыми владеют суперюзеры, потому что получают права суперюзера при выполнении при установленном setuid битом
**setuid** (set user ID) — это специальный бит прав доступа в Unix-подобных ОС, который заставляет программу **выполняться с правами владельца файла**, а не пользователя, который её запустил. Иногда ОС защищает пользователя от самого себя
