#### Defragmenting Disks
Благодаря блокам почти не возникает внешняя фрагментация. Тем не менее сами блоки могут быть раскиданы по диску -> плохая производительность. программка defrag в windows это и делает. Фрагментация быстро работает, когда есть много свободного пространства - можно копировать блоки файлов туда и объединять. Некоторые файлы двигать нельзя - paging файл - (область подкачки), файл гибернации - (копирует RAM при режиме глубокого сна).  На некоторых системах они представляют из себя непрерывные области памяти. Единственный момент, когда их нужно двигать - когда они находятся в конце раздела, а пользователь хочет уменьшить конец раздела - тогда их нужно  удалить, и потом заново создать. Но вообще пишется их дефрагментировать не надо, потому что слишком запарно с точки зрения безопасности. ext3, ext4 меньше страдают от дефрагментации, чем NTFS.

#### Compression and Deduplication
Для уменьшения количества затраченного на диске места используется **compression** - сжатие. Можно сжимать вручную, некоторые ФС автоматически сжимают некоторые файлы и папки. NTFS - предлагают сжатие, как опцию. Алгоритмы сжатия обычно ищут повторяющиеся последовательности данных, которые затем кодируются. Одинаковая последовательность из 133 байтов на разных позициях в файле может быть закодирована 1 числом. То же самое касается и целых файлов, можно хранить один файл для нескольких юзеров.
Также некоторые ФС реализуют дедупликацию - удаление копий - то же самое, что и в paging системе. Большинство ФС реализуют дедупликацию для чанков фиксированного размера, например 128КБ. Чанки между файлами делятся CoW.
inline deduplication ФС вычисляет хэш для каждого чанка, который она хочет записать и сравнивает его с другими чанками. Если чанка уже существует, то ФС добавит его любо в специальное таблицу, либо в иноды, зависит от реализации. post-process делает все то же самое но в фоне. Коллизии обрабатываются последующим полным сравниванием.
