#### File naming +  File Structure + File types
Пользователь не должен знать о том, как и где сохраняется информация на диске и как диски работают.  Одна из характеристик такой абстракции  - имя. Когда процесс создает файл, он дает ему имя, когда процесс завершается, файл остается и к нему можно обратиться по имени. Какие имена разрешены, зависит от ОС. Также часто имя файла состоит из самого названия и расширения, которое показывает что-то о файле. Однако на UNIX-like системах расширения необязательны - тем не менее с ними удобно работать. Короче говоря расширения больше нужны для пользователя, нежели для ОС. Хотя какие-то программы могут отказаться выполнять действия над файлами, если не увидят нужного расширения, например компилятор.
Windows поддерживает несколько файловых систем - **FAT-32**, **NTFS**, **ReFS (Resilient File System)**. ReFS используется на Windows Server. Также есть более новая версия FAT систем - **exFat** - оптимизировала работу с flash памятью, и большими файловыми системами. Конкретно на моем компе NTFS - диски в него форматируются.

Есть несколько подходов того, как устроены файлы. 
1) Самый частый - файл - просто последовательность байтов. Windows и Linux/Macos используют такой подход. Он дает гибкость.  Пользователь может помещать в файл что угодно - ОС не знает что.
2) Файл разбит на записи, каждая с какой-то внутренней структурой. Системные вызовы read() - write() работали только с 1 записью. Она была полезна, когда на тейпе было много колонок - каждая колонка - 1 запись. Сейчас как чистая FS не используется.
3)  Файл разбивается на записи, каждой записи присваивается индекс. Строится сбалансированное дерево поиска (на таком уровне хэш таблицы нет) по лексикографическому убыванию, далее просто ищем. То есть к записи обращаемся по индексу - **index files**. Такой подход используется на больших мэйнфреймах, чтобы не читать полностью огромные файлы, чтобы найти id пользователя, например.
____

1) **Regular Files** - содержат пользовательскую информацию. Это либо бинарные файлы, либо ASCII файлы - (файлы с текстом). ASCII удобны тем, что это могут быть любые файлы с текстом, их можно открыть в любом текстовом редакторе. При IPC не нужно думать о том, что файл не того формата, или программа передаст что то не то. 
   Бинарники отличаются тем, что если их открыть обычным текстовым редактором, то получим мусор. Хотя они тоже представляют собой просто последовательность байтов ОС выполнит его, только при определенном формате.  Важно отличать бинарные файлы от исполняемых. jpg, pdf, zip - тоже бинарные файлы, но их нельзя запустить как exe. Их отличие в том, что чтобы их *выполнить* требуется специальное ПО, вроде фоторедактора.  В канвасе структура бинарника

2) **Directories** - системные файлы, для реализации структуры файловой системы
3) **Character special files** - файлы для моделирования последовательного IO - (не дисков) - all is a file.
4) **Block special files** - файлы для моделирования дисков.
