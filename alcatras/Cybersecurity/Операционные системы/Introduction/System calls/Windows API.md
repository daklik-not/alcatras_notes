Все описания выше относятся к UNIX-like системам. Теперь рассмотрим Windows. В UNIX программы обычно работают проактивно (сами управляют выполнением операций). В Windows GUI-программы используют событийно-ориентированную модель: основной цикл ожидает события (клики, сообщения ОС), на которые реагирует код. В UNIX: прямое соответствие между системным вызовом и библиотечной функцией (примерно 100 вызовов в POSIX). В Windows: Microsoft предоставляет WinAPI (Win32/Win64 API) — высокоуровневый интерфейс, абстрагирующий реальные системные вызовы. Это позволяет менять реализацию системных вызовов без нарушения совместимости. Один WinAPI-вызов может использовать несколько системных вызовов ядра. В Win32 API очень много вызовов, однако не все они системные. Поэтому в Windows невозможно определить какой вызов является системным а какой нет. Поэтому рассмотрим только те, которые уже разбирались в статье про UNIX. 
`CreateProcess` - выполняет работу fork + execve. В нем можно указать множество параметров, как созданный процесс будет себя вести, однако здесь они не рассматриваются. В Windows нет строгой иерархии процессов (как родитель-потомок в UNIX), поэтому после создания все процессы равны
 `WaitForSingleObject` используется для ожидания завершения процесса. 
 `ExitProcess` завершает текущий процесс. 
 Системные вызовы, связанные с файлами очень похожи на их аналоги в UNIX. `CreateDirectory` - создает директорию.
  `SetCurrentDirectory` - изменяет текущую рабочую директорию (аналог chdir).
   Стоит добавить, что Win32 не слишком согласованный интерфейс, из-за привязки к прошлым версиях ОС.
