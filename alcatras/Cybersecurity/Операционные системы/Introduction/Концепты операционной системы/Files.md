_**File system**_  
Очевидно, system calls нужны для создания, удаления, чтения и записи файлов. **Перед чтением файл должен быть найден на устройстве хранения и открыт.** После **работы с файлом** его нужно закрыть. Все это обеспечивается system call’ами.
Чтобы организовать хранение файлов, большинство ОС использует **каталоги (directories)**, которые иногда называют **папками (folders)**. **Иерархия каталогов — это и есть файловая система.** Она работает как дерево и может быть очень глубокой.
Каждый файл в этой иерархии определяется своим **путём (path name)**, начиная от **корневого каталога (root directory)**.
Кстати, важная инфа: в Windows для разделения путей используется обратный слеш (`\`), **а в Linux/macOS — прямой (`/`)**
У каждого процесса есть своя **текущая рабочая директория**. Благодаря этому, если файл лежит в той же папке, что и процесс, можно указать просто его имя (**относительный путь**) вместо полного (**абсолютного пути**).
Перед чтением/записью файл **обязательно нужно открыть** (`open()`). При открытии система **сразу проверяет права доступа** (разрешения) процесса к файлу. Если права есть — ОС возвращает **file descriptor** (fd) — маленькое неотрицательное целое число. Если прав нет — возвращается ошибка. Этот fd потом используется во всех операциях с файлом: чтении (`read()`), записи (`write()`), закрытии (`close()`).
#mount
Теперь про внешние хранилища (флешки, диски). Когда устройство подключается к компьютеру, ОС его _обнаруживает_. Чтобы получить доступ к его файлам, нужно выполнить **system call — `mount()`**. Он "подключает" (**монтирует**) файловую систему этого устройства в какое-то место (_точку монтирования_) в вашей основной файловой системе. Так две разные ФС объединяются в одно видимое дерево. Стоит заметить, что точка монтирования представляет собой некий пустой каталог. Например пустой каталог на жестком диске. Потом к нему будет монтироваться например флешка.
Некоторые устройства (вроде новой флешки) перед использованием нужно **отформатировать** — создать на них файловую систему (например, FAT-32, exFAT, NTFS, ext4). Это отдельная операция, обычно делается _до_ монтирования.
Если просто воткнуть флешку в компьютер, то ее файловая система изначально не будет видна в общей файловой структуре операционной системы. Именно для этого существует монтирование (системный вызов - **mount**). Корень файловой системы флешки монтируется в какой-нибудь каталог в существующей файловой системе (например, на жестком диске). Однако есть небольшая проблема: файлы, которые _уже находились_ в этом каталоге на жестком диске, временно становятся недоступными, пока смонтирована флешка. Однако эта проблема решается очевидным способом - монтированием в _пустой_ каталог.
Другой важный концепт UNIX систем - **special file** (специальный файл, устройство). Они представляют устройства ввода-вывода как файлы (это принцип "всё есть файл", ну вы поняли). К ним можно обращаться для чтения/записи _похожим_ образом, используя стандартные системные вызовы вроде `read`, `write`, `open`. Есть **block special file** (блочные устройства). Они используются для устройств с произвольным доступом, где данные читаются/пишутся блоками (SSD, HDD - да, блоки там это секторы/кластеры). Есть _**character special file**_ (символьные устройства) - _это другое_, они для устройств, работающих с потоком байт (последовательно), как мышки, принтеры, терминалы. Обычно все эти специальные файлы лежат в директории **/dev/**. Вообще смысл этих special files в том, чтобы предоставить ПО максимально простой интерфейс для работы с девайсами, не вдаваясь в подробности, вроде обработки прерываний.
Если два процесса хотят взаимодействовать между собой напрямую, они могут создать специальный канал связи — **pipe** (труба). Процесс A записывает данные в pipe, процесс Б считывает их оттуда. Оба процесса используют для этого стандартные системные вызовы работы с файлами (`read`, `write`), как если бы это был обычный файл, хотя на самом деле это абстракция ядра. Важно заметить, что данные текут в 1 сторону, для двухстороннего обмена - 2 pipe
