#systemcallext
У операционной системы есть 2 основные функции: дать пользовательским программам определенные абстракции и управлять ресурсами компьютера. В основном взаимодействие между ОС и пользовательскими программами заканчивается на абстракции. Часть с управлением ресурсов выполняется автоматически. ОС общается с аппаратным обеспечением путем системных вызовов (system calls). Рассмотрим подход, используемый в UNIX. Существует системный вызов **read**. У него есть 3 параметра: идентификатор файла (или файловый дескриптор), буфер (куда поместить данные), количество байтов для чтения. Многие современные ОС имеют системные вызовы, выполняющие похожие функции (Linux, Minix 3). Поскольку системные вызовы индивидуальны для каждого оборудования и должны быть написаны на низкоуровневом языке, большинство языков программирования предоставляет библиотеку, в которой содержатся обертки для системных вызовов, чтобы программисту нужно было просто вызвать функцию из библиотеки.  **Shared libraries** - разделяемые библиотеки. Они обеспечивают интерфейс для взаимодействия с ядром. В Windows разделяемые библиотеки называются DLL (Dynamic Link Libraries) и имеют расширение .dll. Они могут располагаться в различных системных каталогах, включая C:\Windows\system32, но не ограничиваются им.
Каждый однопроцессорный компьютер может выполнять только 1 инструкцию в 1 момент времени. Если пользовательской программе необходимо обслуживание от системы, она должна выполнить **инструкцию trap** (перехват) и передать контроль ОС. Далее ОС пытается понять, что именно хочет процесс. Затем она выполняет системный вызов, и после его завершения передает управление программе. Если системный вызов возвращает ошибку, то, например в программе на C, обертка (функция библиотеки) обычно возвращает -1, а код ошибки помещается в глобальную переменную **errno**. Программа должна всегда проверять результат системного вызова на наличие ошибки.

Системные вызовы выполняются в несколько шагов.  Рассмотрим system call **read**.

Системные вызовы выполняются в несколько шагов. Рассмотрим системный вызов **read**. **count = read(fd, buffer, nbytes);** Сначала программа подготавливает параметры, сохраняя их в регистры, а если их не хватает, то на стек процесса. Например, на процессорах x86-64 в Linux, macOS, Solaris и других ОС придерживаются **calling conventions**. По ним, первые 6 параметров помещаются в RDI, RSI, RDX, RCX, R8, R9. (step1-3) Важно отметить, что вторым параметром передается именно адрес буфера, а не его содержимое. После этого программа вызывает процедуру из библиотеки (step4). Далее процедура помещает номер системного вызова туда, где операционная система ожидает его увидеть, например в регистр **RAX**. (step5) 
Важно отметить, что номер, это как бы ключ процесса, а не его персональный уникальный номер. Затем процедура выполняет **инструкцию trap** (например SYSCALL на x86-64) для перехода из пользовательского режима (user mode) в режим ядра (kernel mode). Эта инструкция передает управление по **фиксированному** адресу в ядре. (step6) Аппаратно сохраняется адрес возврата (адрес следующей инструкции после trap). Код ядра ОС определяет системный вызов по номеру в RAX, затем находит его обработчик через таблицу указателей, индексируемую по номерам системных вызовов (step7). Далее запускается обработчик системного вызова (step8). После выполнения обработчика ядро возвращает управление библиотечной процедуре в пользовательском режиме (step9). Затем процедура возвращает результат пользовательской программе (step10). После этого программа продолжает выполнение со следующей инструкции.
