Файлы заголовков включаются с помощью ```#include <smth>```
Для того чтобы построить ОС, каждый файл с расширением .c компилируется в **object file**. Объектные файлы, которые имеют суффикс .o, содержат машинный код в виде бинарных инструкций для целевой архитектуры. Позже они будут выполнены CPU.  
Первый этап осуществляется **C preprocessor**. Каждый раз, когда препроцессор встречает директиву `#include`, он проходит по ней и буквально копирует содержимое заголовочного файла в исходный файл. Также он раскрывает макросы и обрабатывает условную компиляцию. На выходе для каждого исходного файла .c получается один временный файл с уже подставленным кодом заголовков. Далее этот обработанный файл компилируется в объектный файл с форматом **.o**. В контексте ОС, которая очень большая, возникает проблема: когда меняется один файл, очень затратно перекомпилировать все приложение. В Unix-подобных системах есть программа **make**, которая считывает **Makefile**, содержащий информацию о зависимостях файлов. Таким образом, если меняется какой-то файл, с помощью этой программы перекомпилируются только те модули, которые от него зависят а потом еще раз пройдут линковку(линковка намного быстрее компиляции).
Как только все объектные файлы готовы, они передаются в программу под названием **linker**, которая объединяет их в один исполняемый файл с бинарным кодом. На этой стадии разрешаются ссылки на функции из библиотек и определяются адреса в памяти. После линковки получается одна исполняемая программа, которую исторически называют **a.out** на UNIX-подобных системах, хотя современные компиляторы по умолчанию часто используют другие имена.
