#linux_security_commands 
**Administration**
```
sudo adduser name - добавляет пользователя с нужным именем
sudo deluser -r name - удаляет пользовател с нужным именем
sudo passwd user - устанавливает пароль
Хэш паролей хранится в etc/shadow (и еще куча полезной инфы, которую нет смысла писать в кратких заметках)
etc/passwd - хранит инфу о пользователях
etc/group - информация о группе.
sudo vipw редактирует etc/passwd
sudo usermod - можно менять различные настройки пользователя, очень вариативная настраивается флагами, лучше посмотреть через sudo usermod --help (например можно добавить в другую группу - sudo usermod -a -G "group" username)
sudo passwd -l name временно блокирует пользователя
groups показывет какой группе принадлжеит пользователь
su - user - переключение на другого пользовател
su - $USER рестартает сессию пользователя
sudo passwd -u name разблокировка пользователя
whoami - показывает текущего пользователя
id -  показывает id пользователя
sudo visudo - показывает пользователей, которые могут выполнять команду sudo
getent group [groupname] - выводит пользователей группы.

```
**Permissions**
```
d | rwx | r-x | r-x - разрешения файла. Первый - тип файла, то есть в этом примере директория, обычно будет просто -. 
Второй -  разрешение юзера
Третий - разрешения группы
Четвертое - все остальные пользователи системы
r - readable, w - writable, x - executable, - -empty
Для директории - возможность посмотреть файлы, возможность переименовывать и удалять файлы, возможность войти в директорию.
Примеры.
-rw-rw-r--  1 daklik-not daklik-not   217 Sep 11 10:24 12.cpp
нет бита x, потому что текстовый файл нельзя выполнить
-rwxrwxr-x  1 daklik-not daklik-not 16696 Sep 11 11:20 21	есть бит x, поэтому файл можно запустить
chmod [u|g|o][+|-][r|x|w] - изменение прав на разрешение.
	можно менять числами,й типо chmod 755, где r - 4, w - 2, x - 1;
sudo chown user file - пользователь становится владельцем файла
sudo chgrp group file - файл принадледит группе group. Для директорий можно использовать флаг -R. Это рекурсивно присвоит все файлы к нужной группе
sudo chown user:group file - и файл и группа
umask - разрешения по умолчанию(umask 021 - здесь пишутся наоборот какие разрешения надо убрать. Типо для пользователей все, для групп убираем запись, для остальных убираем выполнение)
sudo chmod u+s filename  - тепреь для любого пользователя файл будет запускаться от имени владельца. Если поставить S, то это то же самое но без прав на выполнение. g+s тоже самое, но типо выполняется как для участника группы.
sticky bit (+t) в данном каталоге файлы может удалять и переименовывать только их владельцем, владельцем папки или суперюзером.

```
**Типы пользовательских ID**
**Real user id**  -  реальный id пользвователя, который запускает процесс.
**Effective user id**  -   id, который является как бы пропуском. То есть например при установке бита s в файле, при открытии система будет видить его как root
**Saved user id**  - id, который позволяет процессам откатиться назад.
Они имеют определенный смысл. Например при редактирования паролей пользователей. Их может  менять только настоящий судо, а не фейково созданный с помощью бита s.й
