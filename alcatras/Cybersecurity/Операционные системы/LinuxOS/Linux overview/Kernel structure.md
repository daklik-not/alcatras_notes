#### Структура ядра
Ядро сидит прямо перед железом. На самом низком низком уровне находятся обработчики прерываний и диспатчеры процесса. Эти диспатчи происходят, когда происходит прерывание. Низкоуровневый код останавливает процесс, сохраняет его состояние в структуры ядра процесса(PCB например) и запускает нужный драйвер. Диспатч также происходит, когда ядро завершает некоторые операции и нужно запускать процесс(это не планировщик).  
Короче говоря, диспетчер это низкоуровневый код, который выполняется, когда нужно сделать context-switch. А планировщик отвечает за то, какие процессы нужно выгрузить(то есть оба уровня планировщика просто выбирают нужный процесс, а диспатчер уже сам делает все операции по смене контекста, описанные выше)

Далее, ядро разбивается на 3 компоненты

**IO компонента**
IO компонента(отвечает за все операции с IO). Все эти операции интегрированы под **Virtual File System(VFS)**.  Ну короче VFS это интерфейс для системных вызовов. То есть read из libc переводит в системный вызов read, а syscall переводит в vfs_read. VFS вызывает конкретные реализации, например конкретную FS. Далее все операции проходят через драйвера устройства. Для каждого типа устройств свой софт(смотреть картинку:
Для **символьных** устройств есть 2 типа 
	- Когда вводится по 1 символу: ты вводишь символ, он сразу передается программе.
	- Когда вводится целая строка, которая копится в буфере ОС и потом только передается программе. Такая штука называется **line discipline**. 
	Ну короче примерно так это выглядит:

	При этом терминал используется только для текстовых устройств и взаимодействий - например, клавиатура, шеллы, ssh и т.д.

Для **сетевых устройств**  
Слой над сетевыми драйверами выполняет функцию маршрутизации.  В общем он пересылает пакеты куда надо.  Большинство систем содержит полную программную поддержку пересылок - то есть можно на уровне железки понимать куда отправлен пакет и сразу его пересылать, а можно сначала считать пакет, потом ядро поймет что он к нему не относится  и само отошлет его куда-надо. 
Маршрутизация часть кода отвечающего за  весь стек протоколов TCP/IP. 
Над ним находится сокеты - программная абстрация с помощью которой программа может устанавливаться TCP соединение, закрывать ее и передавать по нему данные. 
Сокет это тоже файл - программе дается fd сокета.

Для **блочных устройств** 
Над драйверами устройства находится *IO* планировщик, который отвечает за уменьшение *seek* времени и выполняет другую политику системы
Далее над ним находится **generic block layer**.  Он прячет определенные особенности устройства от FS.  Короче говоря FS не должна обращаться к определенному драйверу устройства - она должна просто прочитать. А сам драйвер уже выбирает **generic block layer**
Далее идет FS.
***

***Memory Management, Process Management компонента***
*Управление памятью* включает в себя реализацию перевода виртуальных страниц памяти в реальные,  реализация кэша страниц, реализация хорошей политики замены страниц и on-demand доставать страницы из памяти

*Управление процессами* - создание и завершение процессов, планирование потоков и процессов, обработка сигналов.

На вершине ядра находятся системные вызовы, которые дают  интерфейс в ядро.
