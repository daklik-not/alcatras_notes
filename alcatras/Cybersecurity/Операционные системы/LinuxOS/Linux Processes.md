### Implementation of Processes and Threads in Linux 
У каждого процесса есть пользовательская часть. Однако после того как 1 из его потоков выполняет системный вызов происходит переход в контекст ядра. Теперь этот поток работает со стеком ядра процесса и программный счетчиком процесса.

В Linux ядро представляет процессы как **tasks** через структуру *task_struct*.  Структура используется для представления любого вычислительной сущности - потока.  Само ядро Lin ux многопоточно.  Для каждой структуры создается дескриптор процесса(типа task_struct), который находится в памяти все время и содержит информацию для ядра(управление).

____

Вообще этот файл находится в оперативной памяти, но для пользовательских программ ядро создает представление, которое находится в $/proc/PID.

Ядро организует все процессы, как двусвязный список, где PID можно сопоставить с адресом task_struct и получать напрямую. Короче это хэш-табличка, как я понял.
Процесс может получать сигналы, когда он находится в swap - по этой причине информация о сигналах должна быть всегда в памяти, даже когда процесс не в памяти. А информацию о дескрипторах можно спокойно выгружать.

Есть несколько категорий информации:
1.  Параметры планирования - приоритет процесса, CPU-burst недавний, sleep-time недавний.
2. Дамп памяти. Указатели на разные сегменты стека. Когда процесс не в памяти, в памяти хранится информация о том, как найти его на диске.
3. Сигналы. Маски, показывающие, какие сигналы игнорируются, какие блокируются, какие в процессе доставки(уже отправлены, но еще не обработаны)
4. Машинные регистры. Когда trap происходит в ядре, то машинные регистры сохраняются здесь
5. Состояние системного вызова. Информация о текущем системном вызове, включая параметры и результат.
6. Таблица дескрипторов на иноды
7.  *Accounting* - указатель на таблицу, которая отслеживает пользовательское и системное время, используемое процессом. Некоторые системы реализуют с помощью этой информации ограничения.
8. Стек-ядра - фиксированный стек, используемый ядром во время kernel-части процесса.
9. *Miscellaneous* - состояние текущего процесса, событие, которого он ждет и другие данные

### Threads in Linux
В многопоточных системах возникает куча проблем с тем, как работать с  потоками(клонирование потоков в fork(), обработка сигналов, IO блокировка).
Linux поддерживает kernel-level потоки
Для Linux был разработан системный вызов ***clone()***. Его смысл в том, чтобы сделать множество свойств уникальными не для процесса, а для потока. Например: файловые дескрипторы.
```c
pid = clone(function, stack ptr, sharing flags, arg);
```
Этот вызов создает поток в текущем процессе или в новом процессе, в зависимости от *sharing flags*. 
В обоих случаях поток начинает выполнять функцию, переданную через *arg*. Также в обоих случаях потоки получают свой собственный стек, с указателем на stack_ptr.
***Sharing flags***
Они позволяют более точно настраивать создание потоков.

| Flag          | Meaning when set                                                                                                                     | Meaning when cleared              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------- |
| CLONE_VM      | Копирует виртуальное пространство - поток создается внутри текущего процесса                                                         | Де-факто создание нового процесса |
| CLONE_FS      | Даже если старый и новый поток имеют свое адресное пространство они все еще разделяют рабочие директории                             | Не разделяет(                     |
| CLONE_FILES   | Аналогично разделяет файлы                                                                                                           | Не разделяет(                     |
| CLONE SIGHAND | Аналогично разделяет обработчики сигналов                                                                                            | Не разделяет(                     |
| CLONE PARENT  | Определяет родителя дочернего потока. Это может быть, как родитель вызвавшего потока, так и сам вызвавший поток может быть родителем |                                   |
Также в Linux различают между **PID** и **TID**

### Синхронизация Linux

Раньше был  *BKL - Big Kernel Lock*. Это значит, что в ядре в момент времени мог быть только 1 поток. По понятным причинам в 2017 году от него полностью избавились.

На самом низком уровне Linux предоставляет обертки вокруг аппаратно-поддерживаемых атомарных инструкций, таких как *atomic_set* и *atomic_read*.  Поскольку современный *hardware* может переопределять порядок операций с памятью Linux предоставляет *барьеры* - операции *rmb*, *wmb*.

Чаще используются более высокоуровневые. Потоки, которые не хотят блокироваться(например, когда знают что блокировка будет очень короткой) могут использовать *ticket-based* спинлоки. В качестве мьютексов и семафоров используется *mutex_trylock*, и *sem_trywait*. Также используются фьютексы, RCU.

Когда обычный код ядра и обработчик прерывания работают с общими данными, Linux при заходе потока в критическую секцию может просто отключить прерывания.
