Процессы создаются с помощью ***fork()***- от родительского к дочернему. Main memory делится CoW, а для обычных файлов изменение в файле одним процессом будет видно другим процессом. 
В дочернем fork() вернет 0, а в родительском pid дочернего.
Пример:

```c
int main() {
    int pid = fork();
    if (pid < 0) {
        std::cout << "fork failed" << std::endl;
    } else if (pid > 0) {
        std::cout << "currently in parent" << std::endl;
    } else {
        std::cout << "currently in chind" << std::endl;
    }
}
Вывод: 
	currently in parent
	currently in chind
```


Чтобы подождать завершения дочернего процесса используется ***waitpid***().

В большинстве случае дочерний процесс должен выполнять другой код.
Чтобы дочерний процесс выполнял не родительский код используется ***exec()***. После *exec()* заменяются все структуры ядра процесса. Здесь чуть подробнее:
1. name - имя программы, которую надо выполнить
2.  argv - указатель на массив аргументов
3.  envp - указатель на массив окружения.

Главная функция программы(имя который передали через name) содержит 3 аргумента: main(argc, argv, envp).
1. *argc* - число элементов в строке командной линии(здесь рассматривается cp программа CLI)
2. *argv* - элемент $i$ этого массива указывает на $i$ элемент строки  командной линии
3. *envp* - указатель на среду, массив строк, содержащий пары *name=value*, содержащий информацию такую как тип терминала или имя домашней директории программы.

***exit()*** - просто завершает программу с нужным статусом. 
Есть такие *зомби-процессы*. Они возникают, когда процесс уже фактически завершился, его структуры были очищены, но остается запись **PID+exit_status**, поскольку дочерний процесс еще никто не ждет. Как только родительский процесс начнет его ждать, процесс сразу полностью очистится.

Некоторые системные вызовы связаны с сигналами
1. ***sigaction()***. Обьявляет о том, что хочет отлавливать сигналы.  
	  Параметры: 
	1. сигнал, который надо поймать 
	2. указатель на структуру, дающую указатель на процедуру обработки сигнала 
	3. указатель на структуру, куда возвращается информация об обработке сигналов.
	Пример:
```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>
void handler(int sig) {
    printf("Получен сигнал %d\n", sig);
}
int main() {
    struct sigaction sa;
    // Настройка структуры
    sa.sa_handler = handler;     // устанавливаем обработчик
    sigemptyset(&sa.sa_mask);    // очищаем маску блокируемых сигналов
    sa.sa_flags = 0;             // без флагов (поведение как у signal)
    // Установка обработчика для SIGINT (Ctrl+C)
    if (sigaction(SIGINT, &sa, NULL) == -1) {
        perror("sigaction");
        return 1;
    }
    printf("Нажми Ctrl+C (PID: %d)\n", getpid());
    while(1) {
        pause(); // ждем сигнал
    }
}
```
Обработчик может работать бесконечно, но на практике очень мало, после обработки возвращается в точку от которой был вызван
2. ***kill*** - процесс посылает сигнал другому процессу.
3. ***alarm()*** -  параметр определяет в секундах после которого SIGALRM посылается процессу. Много alarm() последовательно отменяют друг-друга. Если alarm игнорируется, то процесс(тот который вызвал alarm на себя) убивается.
4. ***pause()*** - приостанавливает вызывающего до следующего сигнала.
