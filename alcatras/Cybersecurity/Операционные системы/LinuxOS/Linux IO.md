#### Networking
Ключевой концепт сети на уровне ОС это ***socket***. Сокеты аналогичны ***mailbox***.
![[Cache/Pasted image 20260518171533.png]]
Сокеты можно создавать и удалять динамически. Создание сокета возвращает файловый дескриптор, который надо использовать примерно для всех операций в сети. Каждый сокет поддерживает свой тип нетворкинга(определенный при создании).
1. Reliable connection-oriented byte stream. Ну это TCP. Приходят байты, а сокет гарантирует что до процесса байты дойдут в нужном порядке.
2. Reliable connection-oriented packet stream. По идее то же самое, но минимальная единица передачи пакет - каждый пакет придется вручную запрашивать.
3. Unreliable packet transmission. UDP - никаких гарантий.

Адрес сокета в сети - IP+port
Для установления соединения 1 сокет выполняется системный вызов *listen*, который создает буфер блокируется до того как придут данные. Удаленный делает *connect* системный вызов передавая в качестве параметра дескриптор локального сокета и адрес удаленного сокета. Если 1 сокет принимает соединение, он создает новый сокет для двухстороннего соединения. Потом для получения данных процессу достаточно просто читать данные по дескриптору, а для закрытия просто использовать close()

#### Input/Output System Calls in Linux
Помимо стандартных обращений к файлу устройства иногда нужны специальные настройки

Вообще символьные устройства работают с псевдотерминалами *pty:  /dev/pts* или терминалами. 
Псевдотерминал состоит из главного и подчиненного. Подчиненное(**slave**) предоставляет процессам терминальный интерфейс не опирающийся на прямую аппаратную поддержку. Эти данные становятся вводом для главного.
