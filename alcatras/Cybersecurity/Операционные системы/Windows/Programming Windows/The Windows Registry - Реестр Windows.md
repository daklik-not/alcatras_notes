
Мы знаем, что пространство имен создается каждый раз при запуске системы.  Чтобы корректно его создавать Windows реализует специальный тип ФС - **реестр**. Он нужен, например для инициализации устройств в *DosDevices*. 
Реестр организован в раздельные тома, которые называются кустами. Каждый куст хранится в отдельном файле *C: \ Windows \ system32 \ config*.  Когда Windows запускается куст, который называется **SYSTEM**, загружается в память boot программой. 
В SYSTEM кусте хранится информация о том, какие драйверы использовать с какими устройствами, какое ПО запускать изначально и другая. Короче говоря она используется при запуске boot программкой. 
Другие кусты используются после загрузки системы, чтобы описывать софт установленный на системе, пользователей, установленные **COM** обьекты. Информация об авторизации хранится в **SAM - Security Accesss Manager**.  На картинке представлены различные кусты

У реестра есть несколько проблем. Первая в том что пользовательские программы сохраняли конфигурационную информацию неорганизованно что привело к их пересечению. А вторая проблема в том, что если программа запускалась от админки, она могла положить всю систему просто редактируя системные части реестра.
Для современных программ *MSIX* реализован следующий механизм - программа думает, что пишет в системный реестр, а на самом деле пишет в специальное место реестра, уникальное для этого приложения и пользователя. Это очевидно немного все структурирует и не дает программе так легко ломать систему.
