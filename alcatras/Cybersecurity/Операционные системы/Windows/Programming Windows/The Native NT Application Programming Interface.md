Нативные системные вызовы практически не публикуются публично. Они реализованы в **NTOS** слое выполнения, который работает в режиме ядра. Они оперируют над объектами, к которым доступ осуществляется через ядро. Они на картинке
![[Cache/Pasted image 20260710201142.png]]
Каждый вызов возвращает тому, кто его вызвал специальный обьект - **handle**. Это некий аналог дескриптора с той разницей, что он не только для файлов.  Он используется для выполнения операций над объектом. В общем случае handle не может быть использован другим процессом, но при определенных обстоятельствах это можно сделать, но при этом у процесса, передающего должен быть *handle* другого процесса
У каждого объекта есть *security descriptor*, который говорит, кто может выполнять операции над объектом, а кто нет.  Например можно указать в нем, что во втором процессе, обьект будет *read-only*.

Также в ядре реализована такая штука, как **object manager**.  Он позволяет использовать обьекты, используя их имена. Object manager использует **NT пространство** имен. Оно представляет из себя иерархичное дерево директорий, символических ссылок и объектов.  Короче я особо не понял, но вроде у object manager есть какие-то исполнительные составляющие, которые отвечают за управление конкретным типо объекта.

Но если вкратце, то когда резолвится путь *\Device\HarddiskVolume1\Users\Me\file.txt*, то в пространстве имен будет только первые элемента, остальное скидывается в драйвер ФС, который был как раз таки найден с помощью пространства имен. Это пермаментный обьект. Далее вступает в игру парсер
Пространство имён содержит только объект тома (устройства), а все файлы внутри него «прицепляются» к этому объекту через остаток пути. 
___
ОС сама часто использует обьекты.  В частности для того, чтобы пользоваться удобствами *object manager*.  Также обьекты удобно передавать между компонентами ОС.  Например, когда подключается устройство, для него создается *device object* и далее по этому обьекту ссылаемся на его драйвер.
Названный обьект может быть помечен, как *permament - постоянный* - он продолжит существовать, даже если ни у 1 процесса нет хэндла на него. Используется для разделяемой памяти, обьектов синхронизации, обьектов драйверов.
