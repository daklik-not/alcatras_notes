#smss
Мы говорим о том, что не всегда напрямую вызывается ядро, как описано здесь #windows_chain
NT ядро изначально запускает процесс smss.exe - самый первый пользовательский процесс. Он с помощью CreateProcess запускает crss.exe для Win32. Остальные создаются через CreateProcess.
Пройдемся по порядку

Процесс обращается к библиотекам подсистемы, которые нужны чтобы соединить процесс и ядро. Они реализуют функции специфичные для подсистемы. После обращения к библиотекам вызывается  CreateProcess(например), который перехватывается и направляется в тот код подсистемы, которая ему нужна.  Далее  приложение отправляет  LPC сообщение(**полноценная высокоуровневая инфраструктура IPC**) через  ядро которое обращается в процессу подсистемы(**маршрутизирует**).  Всем остальным занимается ужеd процесс подсистемы.  Также в самом ядре должна быть определенна поддержка подсистемы. Процессы подсистемы используют **нативные NT системные вызовы**. Процесс подсистемы общается с пользовательским процессам специальными LPC структурами с информацией, которая нужна для выполнения запроса, в данном случае структурка описывающая процесс.
