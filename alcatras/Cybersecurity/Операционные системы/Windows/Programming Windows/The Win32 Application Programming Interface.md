Хотя Win32 в теории дает обратную совместимость, то есть программы должны быть запущены на других версиях  Windows. На практике Windows настолько сложен, что малейшее изменение может привести к ошибке. 
Есть еще несколько специальных сред выполнения - WOW(Windows-On-Windows). Оно используется для перевода n-битных приложений в x-битных. WoW32 больше не поддерживается. WoW64 позволяет запускать 32 битные x86 приложения на arm64 hardware. с помощью эмуляции инструкций

**Windows MMAP**
В Win32 кучу вызовов для управления процессами, но при этом большая часть для управления памятью недоступна, доступны *memory-mapped* файлы.  При этом ОС сама реализует demand-paging.  Она делает это, комбинируя 3 средства:
1. Она дает Win32 интерфейсы, которые позволяют процессу управлять свои виртуальным адресным пространством, в частности резервировать диапазоны адресов. 
2. Win32 поддерживает такую абстракцию, как **file mapping**, которая используется чтобы предоставлять адресуемые обьекты, такие как файл. Чаще всего оно реализуется с помощью хэндла, который связан c системным кэшем. Вроде этот обьект на самом деле называется **Section** - он как и все обьекты представлен хэндлом
3.  Создать *view-представление* - вставить обьект в виртуальную память конкретного процесса(можно даже другого процесса, но если у тебя есть хэнлд + только через нативные системные вызовы).

**FS**
Также есть куча вызовов для работы с файлами. Помимо стандартных вызовов, файлы и тома могут быть зашифрованы, можно получить доступ к журналу тома, который пишет все изменения в файл.  Тома находятся в пространстве имен. Есть специальные *repase-point*, то что написано в заметке про NT интерфейс.

**IO**
Модель полностью асинхронная.  Однако можно вручную указать, какое IO должно быть синхронным -  в Win32 многие процедуры можно вызвать так, чтобы они были синхронные

**Security**
Каждый поток ассоциируется с объектом ядра, который называется **токен**, который содержит информацию о сущности и привилегии каждого потока.  У каждого объекта есть **ACL - Access Control List**, который подробно описывает. какие пользователи могут использовать его и и какие операции над ним выполнять.

**Пространство имен**
Win32 — это **виртуальное представление**, которое проецируется на единое, фундаментальное дерево **пространства имён NT (Object Manager Namespace)**
Только части пространства имен NT видны в пространстве имен Win32
. \DosDevices\C: содержит символическую ссылку на \Device\HarddiskVolume1.  И так с другими обьектами 

Также есть вызовы для управления графическим интерфейсом.  Это работает через специальный win32k.sys драйвер, к которому получаем доступ через специальные интерфейсы Win32.
