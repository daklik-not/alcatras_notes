#### Hypervisor
**Hypervisor (Гипервизор первого типа)** работает напрямую на железе. На нем можно запускать много ОС одновременно, каждая в своей изолированной виртуальной машине — **partition**.
Гостевая операционная система работает на виртуальном процессоре (vCPU). Если упростить, гипервизор запускает потоки vCPU (по 1 на физическое или логическое ядро процессора), выделяет каждому квант времени, и они конкурируют между собой.
Большая часть операций гостя выполняется напрямую на реальном процессоре на полной скорости(то есть рут партиция ОС  с помощью гипервизора выделяет VCPU для гостевой ОС, после чего благодаря поддержке аппаратной виртуализации мы напрямую работает с процессором). Исключение — **привилегированные операции** (например, попытка отключить прерывания). Процессор блокирует их выполнение гостем, генерирует процессор выполняет VM-exit — аппаратное переключение в root mode, где управление получает гипервизор и передает управление гипервизору. Гипервизор безопасно эмулирует эту операцию для гостя и возвращает его к работе.
**Работа с устройствами ввода-вывода (I/O):**  
Короче говоря, гостевая ОС просто обращается через Win32 также как обычно. Этот запрос перехватывает гипервизор. В ядре рут партиции есть специальный процесс для каждой ОС. Ядро отдает ему этот запрос, после чего этот процесс выполняет нужные для гостевой операции на рут партиции.
**Безопасность (VSM и VBS):**  
Гипервизор предоставляет **VSM (Virtual Security Mode)**. Он делит память на изолированные зоны: Normal World (где работает обычная Windows) и Secure World.  Или VTL0 и VTL1.
В Secure World запускается **Secure Kernel(SK)**. Это ядро микро-ос. Ядро Windows(ntoskrnl) не может напрямую писать туда - у него неожиданно нет прав. Оно также работает поверх гипервизора. Именно гипервизор решает направить, например, прерывание в VTL1 или VTL0, все вызовы к SK проходят через гипервизор. SK нужен для:
		1. SK смотрит, чтобы программы модулей и драйверов были подписаны Microsoft. Если ядро скомпроментировано, то это поможет не запускать драйверы, которые заинсерчены в ядро или динамически подгружены.
		2. Защитить креденшиалы, которые lsasio(который работает в VTL1) сохраняет в VTL1 память.
