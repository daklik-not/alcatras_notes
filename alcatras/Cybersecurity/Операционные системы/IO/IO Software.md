### IO Software Layers
IO software как правило разбивается на 5 слоев, показанных на картинке ниже.
#### Interrupt Handlers
Прерывания прерывают нормальную работу ОС, поэтому они должны  быть спрятаны от большей части системы. Лучший способ спрятать прерывания - драйвер, который будет начинать IO операцию, затем блокироваться до прерывания с помощью семафоров/условных переменных. Пока драйвер заблокирован выполняется ISR. Это работает лучше всего, если драйвера - процессы.
![[Pasted image 20260216204533.png]]
Последовательность обработки прерывания - тут я в некоторых моментах не очень уверен.
1. Сохранить все регистры, которые не были автоматически сохранены interrupt hardware(это когда процессор при прерывании сохраняет минимальный контекст - например PC).
2. Нужно задать контекст выполнения - корректное АП. По нейронке, виртуальное адресное пространство процесса такое же - но ISR использует стек ядра процесса для работы с данными. Соответственно MMU должен указывать на правильную таблицу страниц.
3. В книге написано про настройку стека, но фактически это уже сделано на предыдущем шаге
4. ОС должна понять, что прерывание принялось в обработку процессором - (не уверен что правильно понял)
5. Сохранение регистров в PCB
6. Запуск ISR, по уже переданному индексу в векторе прерываний. Данные для ISR берутся регистров устройства.
7. Планирование другого процесса
8. Настройка MMU для следующего процесса - он должен указывать на соответствующую таблицу страниц
9. Загрузка регистров процесса
10. Запуск процесса
