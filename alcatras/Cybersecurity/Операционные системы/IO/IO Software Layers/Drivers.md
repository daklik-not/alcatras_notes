#### Device Drivers
Для разных устройств совершенно разные драйвера.  Драйверы должны предоставлять интерфейс для ОС для работы с устройствами. **Device driver** - код, специфичный для устройства и пишется производителем устройства. Драйвера обслуживают конкретный тип устройства или класс(не рекомендуется).

Множество устройств основываются на одной и той же низлежащей технологии. **USB**  - пример этого. USB драйвер включают в себя сразу много драйверов для многих устройств. В низу стека драйвера находится *USB link layer* - аналог *data link layer*, который обрабатывает сигналы и декодирует поток сигналов в USB пакеты. Он используется более высокими уровнями, которое обеспечивает стандартным функционалом. Еще выше высокоуровневые интерфейсы для конкретных типов устройств. Таким образом есть раздельные драйвера, несмотря на то, что стек один. 

Чтобы получить доступ к hardware - регистрам контроллера, драйвер устройства должен быть частью ядра ОС. Тем не менее можно реализовать драйверы в пользовательском пространстве - использовать системные вызовы для получения регистров устройства. Такая архитектура позволяет избежать краша системы при краше драйвера.

Так как драйвер находится в ядре - нужно понимать модель взаимодействия драйвера и ОС. Драйверы классифицируются также, как типы устройств - блочное и символьное. Большинство ОС определяют стандартный интерфейс для блочных(запись блока)/символьных устройств(запись строки символов).

**Структура драйвера устройства**
Когда драйвер получает параметры, он проверяет их валидность и затем, преобразовывает их в реальные данные для контроллера устройства. Например раньше номер блока преобразовывался в номера дорожки, сектора, цилиндра, для SSD драйвер должен передать LBA контроллеру.
Драйвер проверяет, используется ли устройство. Если оно используется, запрос будет поставлен в очередь на обработку. Если нет, статус hardware должен быть проверен, может ли запрос быть обработан прямо сейчас. Возможно устройство нужно включить. Как только устройство готово, начинается управления.
Драйвер это место где последовательность команд определена. Команды записываются на регистры контроллера. После каждой команды нужно проверять, что контроллер принял команду и готов принять следующую.  Некоторые контроллеры могут хранить linked list в памяти и выполнять команды полностью без помощью ОС. 
После передачи команды есть 2 случая - драйверу нужно заблокировать и драйверу не нужно блокироваться. Когда драйвер блокируется его нужно разбудить прерыванием. Если все ок драйвер передает данные и возвращает *error report*. Если еще есть запросы, один может быть выбран и передан на контроллер. Если нет драйвер блокируется и ждет запросы.
Драйвера должны быть *reentrant - возвращающимися* - запущенный драйвер должен ожидать, что во время обработки первой команды, может прийти вторая.
Драйверы не общаются через системные вызовы. Обычно драйверам просто запрещается доступ к определенным вызовам.
