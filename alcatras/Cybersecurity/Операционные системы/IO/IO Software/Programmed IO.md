#### Programmed IO
В такой реализации вся работа по передаче данных скидывается на процессор. Есть несколько шагов работы с устройствами - в книге на пример принтера. 
1. Пользовательский процесс собирает строку в буфере, после чего с помощью системного вызова обращается к устройству. Если принтер используется другим процессом,  то вызов вернет ошибку.
2.  Копирует пользовательский буфер в буфер ядра.
3. 5. У принтера есть специальный бит в регистре статуса - пишет/не пишет. Он устанавливается контроллером . Для записи ОС ждет, пока он не станет готов.
4. Как только принтер готов ОС копирует первый символ строки на регистра данных принтера
5. Принтер может буферизировать символы, тогда результат напечатается не сразу. Если по символу, то напечатается сразу.
В коде наглядно показано, что процессор будет висеть в цикле - busy waiting/polling; Проблема в том, что процессор будет занят все время выполнения IO - это допустимо только если работа IO быстрая - сейчас процессор значительно быстрее почти любого устройства.
```c
copy from user(buffer, p, count);
for (i = 0; i < count; i++) { 
  while (*pr inter status reg != READY);
  *pr inter data register = p[i];
} 
return_to_user( );
```
