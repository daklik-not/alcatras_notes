#### Goals of the IO Software
Есть несколько ключевых концептов IO ПО.

| Цели/концепты                     | описание                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| device independece                | Программист должен писать программы не задумываясь о том, что это за устройство. Цель ОС в том, чтобы унифицировать все это, несмотря на то, что с каждого устройства читается по своему.                                                                                                                                                                                           |
| uniform naming                    | имя файла/устройства должно быть строкой или числом независимо от устройства. Все файлы и устройства доступны по *path name*                                                                                                                                                                                                                                                        |
| error handling<br>                | ошибки должны обрабатываться как можно ближе к hardware. Например, при ошибке чтения контроллер должен сначала  попробовать решить проблему сам. Далее драйвер. Множество ошибок разрешаются через повтороное выполнение. И так далее будет передаваться на верхние уровни ПО                                                                                                       |
| synchronous/asynchronous transfer | когда данные взаимодействует с IO пользовательский процесс должен корректно блокироваться, хотя на самом деле процессор в этом время будет заниматься другой программой. Когда приходит прерывание от устройства процесс должен быть корректно восстановлен. Так же процесс должен быть предоставлен доступ к асинхронному IO - для многопоточных приложений, или асинхронном коде. |
| buffering                         | данные которые приходят с устройства не могут быть напрямую сохранены в юзер буфере - ОС должна куда-то их сохранять. Это значительно нагружает систему.                                                                                                                                                                                                                            |
| dedicated/shared io               | просто нужно обеспечить отделенность устройств друг от друга                                                                                                                                                                                                                                                                                                                        |
