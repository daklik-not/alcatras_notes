## Page tables
В простой реализации виртуальный адрес разбивается на виртуальный номер страницы и биты смещения, как было описано ранее. Виртуальный номер страницы используется как индекс в таблице страниц, чтобы по индексу найти страничный кадр, если такой есть.  Короче говоря цель страниц таблиц в преобразовании виртуальных страниц в страничные кадры.
### Structure of a Page Table Entry
Структура вхождения таблицы страниц разнится от архитектуры. Здесь будет описан наиболее общий вариант для 64 битной архитектуры
**Page Frame Number** - как раз таки то, во что переводится виртуальный номер страницы. Он занимает 52 бита.
**Present Absence Bit** - показывает существует страничный кадр или нет. Если равен 0 - значит страницы нет в памяти.
**Protection bit** - показывает какие типы доступа разрешены. Обычно содержит 3 бита по одному на чтение, запись, выполнение страницы. Под выполнением страницы имеется в виду выполнение инструкции по адресу, на который ссылается страница.
**Supervisor bit** - показывает, какой код может получить доступ к этой странице - только код ядра или также пользовательские программы.
**Modified bit** - когда процесс как то изменил содержимое таблицы от ее последней версии , то в таблице страниц аппаратное обеспечение автоматически устанавливает для него этот бит. Этот бит иногда называют **dirty bit**
**Referenced bit** - показывает, что недавно процесс ссылался на эту страницу. Через какое-то время обнуляется - clock interrupt.
**Caching bit** - нужен, чтобы запрещать кэширование страниц. Он нужен для memory-mapped IO. Короче говоря, это то, как на низком уровне работает концепция все это файл. Кэшированные страницы могут  вести себя достаточно непредсказуемо. Например инструкции процессора могут выполняться не по порядку или в бесконечно цикле могут быть использованы кэшированные неактуальные значения.

Здесь чуть поподробнее. Как я понял, есть такая шутка называется когерентность кэша. В большинстве случаев она относится к многопроцессорным системам, то есть если процессор изменил свой кэш, то он должен уведомить другие процессору о то, что он его изменил. Здесь немного другой случай. Для взаимодействия устройства и процессора нет протоколов когерентности. Пусть процессор читает значение с регистра устройства. Оно кэшируется. Потом значение на регистре меняется, но процессор об этом не знает. Он использует старое кэшированное значение.

Важно заметить, что таблица страниц не хранит информации о том, где на диске находятся данные, которые нужно подкачивать. Причина в том, что таблица страниц используется только аппаратным обеспечением для преобразование виртуальных адресов в физические. Подкачкой занимается уже операционная система.

Также важно добавить, что любой софт использует виртуальные адреса. Включая операционную систему. Должны быть 2 разных таблицы - таблица для ядра и таблица для пользовательских программ. Однако часто просто используют supervisor bit, потому, что смена таблиц страниц - дорогая операция
