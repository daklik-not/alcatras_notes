#### Load Control
Если общее количество страниц рабочего набора всех процессов превысит обьем RAM система начнет пробуксовывать. Один из его симптомов - некоторым процессам нужно больше памяти, но никаким не нужно меньше. 
Самое просто решение - просто убить процессы. На Linux есть **OOM - Out of Memory Killer** процесс. Он активизируется при недостатке памяти, просматривает все процессы, в зависимости от размера, типа(user-kernel), и приоритета. Убивает процесс с самой высокой оценкой. Менее радикальное решение - выгружать процессы на диск. Просто выгружаем, пока page fault перестанут происходить часто. Можно так же загружать с диска процессы, которые занимают меньше памяти. Также нужно учитывать какой процесс - CPU-bound или IO bound. Также можно попробовать уменьшить количество затраченной памяти путем сжатия. Одна известная техника **deduplication** или **same page merging**. Периодически проверять, если 2 страницы в памяти имеют одинаковое содержание. Если оно одинаковое то система удаляет вторую страницу, и в page table делает указатель на первую, с Copy On Write.

**Cleaning Policy**
Алгоритму aging нужны чистые страницы, которые в любой момент можно выгрузить на диск.  Paging системы обычно имею фоновый процесс, который называется **paging daemon**. Если слишком мало чистых страниц, он начинает выгружать страницы с помощью какого-нибудь алгоритма. Странички с modified битом сначала отправляет в пул на запись в диск.
Если страница, которая уже выгружена, но еще не перазаписана - то есть находится в пуле страниц на запись, нужна снова  - ее можно забрать из пула свободных страниц.
Для реализации можно к стандартному clock алгоритму добавить второй hand, который будет вращаться процессом демоном. Если modified бит равен 1, то страница записывается на диск.
