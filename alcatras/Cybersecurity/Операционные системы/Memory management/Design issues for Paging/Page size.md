#### Page Size
Размер страницы определяется операционной системой. Даже если страницы, заложенные в основу аппаратного обеспечения меньше - ОС может просто слить несколько страниц в 1 - программно эмулировать большие страницы.
Недостатки больших страниц. При использовании больших страниц большого размера данные не заполняют страницы полностью. Последняя страница будет не полностью заполнена. Эта память просто теряется. Это называется **internal fragmentation**. 
Недостатки маленьких страниц. Во-первых большая таблица страниц. А нам нужно по ней регулярно бегать + она тоже занимает место в памяти.  Во-вторых маленькие страницы сильнее загружают критически маленький и очень важный ресурс - TLB.
Также стоит добавить, что чем больше страниц - тем чаще page fault - тем чаще загрузка на диск, что очень медленно.
Для балансировки операционные системы часто используют различные размеры страниц - большие страницы для процессов ядра, маленькие для пользовательских.  Некоторые системы даже двигают память процесса, чтобы создать дырку достаточного размера для большой страницы - **transparent huge pages**
Пространство, занятое таблицей страниц увеличивается по мере того, как размер страницы уменьшается. Пусть $s_{bytes}$- process size, $p_{bytes}$ - page size, $e_{bytes}$ - size of each page table entry. Тогда $p = \sqrt{2se}$. Мат доказательство простое, сюда писать не буду.
Cейчас обычно используются страницы по 4КБ
