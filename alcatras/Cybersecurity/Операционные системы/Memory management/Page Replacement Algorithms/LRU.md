#### LRU - The Least Recently used - page replacement algortithm.

Идея в том, чтобы выкидывать страницу, которая не использовалась наиболее большое количество времени. Это статистически работает, потому что страница, которая недавно была использована, с большей вероятности будет использована снова, чем страница, которая не использовалась давно. Такой алгоритм называется **LRU**.
Теоретически его можно реализовать. Но проблема в том, что структуру придется менять на каждый memory reference - а это очень дорого вне зависимости от того, что использовать.
Есть аппаратное решение, оснастить аппаратное обеспечение счетчиком C, который автоматически будет увеличиваться после каждого memory reference. После каждого memory reference он будет записываться в page table entry текущей страницы. Таким образом процесс с наименьшим C и будет тем, который использовался реже всего. Но тут тоже проблема - минимум не то чтобы очень быстро можно искать. Самое быстрое - бинарная куча, или что такое.

#### Simulating LRU in software

Тем не менее не у всех машин есть нужное аппаратное обсепечение для выполнения прошлого LRU. Можно реализовать в software - назвали **NFU - (Not Frequently Used)**.
Используется программный счетчик - изначально равный 0 - для каждой страницы. На каждое прерывание по таймеру, операционная система сканирует все страницы в памяти и к счетчик каждого процесса добавляет его reference бит. При page fault выбирается страница с наименьшим счетчиком.
PS - ОС физически не может прочитать всю таблицу за 1 прерывание. В таком случае используется неточное обновление - то есть обновляем только часть страниц для текущего clock interrupt - lazy aging
Главная проблема NFU в том, что он никогда ничего не забывает. Допустим пример с многопроходным компилятором. В первой проходке используются одни страницы - у них будет высокий счетчик. Во второй другие, но у них у всех был низкий счетчик, поэтому система просто выгрузила их на диск. Таким образом теряется много полезных страниц.
Есть решение этой проблемы - счетчики сдвигаются на один бит вправо, перед добавлением R бита. Также R бит добавляется к самому левому биту. На картинке показана схема работы.
Такой алгоритм называется **aging**
