#### The working set page replacement algorithm

Обычно ОС загружает страницы по необходимости - процесс вызывает page fault, после чего страница загружается. Такой подход называется **demand paging**. Большинство процессов работает так, что на протяжении какого-то  количества  времени по большей части он ссылается на небольшую группу адресов. Это свойство называется **locality of reference**.  Набор страниц, который используется на текущем называется **working set**.  Если память слишком маленькая чтобы хранить весь working set она будет постоянно вызывать много page faultов. Система, которая тратит большую часть времени на подкачку страниц называется **Thrashing**.
На мульти программируемых системах часто процессы полностью выгружается из RAM. Очевидно, что каждый раз подгружать рабочий набор просто неэффективно. Многие paging системы пытаются, загрузить в память рабочий набор процесса до того, как процесс запущен. Это подход называется **working set model**. Загрузка страниц до того, как процесс запущен называется **prepaging**. 
В любой момент времени $t$  существует набор, состоящий из страниц, используемый $k$ самыми частыми ссылками на память. $w(k, t)$ - рабочий набор. Это монотонная неубывающая функция от $k$. Предел этой функции конечен - не может быть больше  всех страниц в адресном пространстве - программы редко используют 1 страницу памяти.
Набор страниц медленно меняется со временем. Содержимое рабочего набора не сильно зависит от выбранного $k$. Поэтому можно сделать предположение о том, какие страницы будут нужны, когда программа перезапускается на основе тех страниц когда она остановилась. Смысл prepaging в том, чтобы на основе этого загрузить заранее в память страницы.
 Для реализации ОС должна знать, какие страницы в рабочем наборе. Чтобы реализовать рабочий алгоритм нужно выбрать значение $k$. Затем после каждого memory reference, набор страниц используемый k самыми частыми memory reference определяется. Например можно создать **shift register** длиной k. На каждый memory reference последний виртуальный номер будет выталкиваться, и новый добавляться. Однако это очень дорого - такой подход не используется.
 Вместо того, чтобы считать набор для каждых k memory reference - будем считать страницы, которые использовались за последние, например 100мс выполнения процесса. Количество процессорного времени реально потраченного процессом называется **current virtual time**. Тогда рабочий набор процесса это набор страниц, на который он ссылался каждые $\tau$ секунд своего виртуального времени. 
 ____ 
 Теперь к самому алгоритму замены страниц. Основная идея в том, чтобы найти страницу, которая не в рабочем наборе и выгрузить ее на диск. Очевидно нам не интересны страницы без present бита. На картинке показана схема работы.

Если referenced бит равен 1, то просто перезаписываем время последнего использования.
Если referenced бит равен 0, то смотрим, если время последнего использования больше выбранного $\tau$  - тогда страница не в рабочем наборе и ее заменяют. Если время последнего использования меньше $tau$ - то страница в рабочем наборе, но она может быть выгружена из памяти, только если все страницы в рабочем наборе.
Такой подход достаточно медленный, поскольку таблицу страниц надо сканить на каждый page fault.
