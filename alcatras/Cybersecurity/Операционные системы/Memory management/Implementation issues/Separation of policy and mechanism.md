#### Separation of Policy and Meachanism
Архитектура memory manager микроядра операционной системы -  Mach
1. Низкоуровневый MMU обработчик - kernel space. Он machine-dependent
2. Page fault обработчик - часть ядра. Он machine-independent
3.  Внешняя страница, запущенная в пользовательском пространстве. Им в большей части определяется политика.у

![[Cache/Pasted image 20260109121513.png]]
Когда процесс запускается, внешний pager уведомляется, чтобы он настроить карту страниц процесса и выделить память на диске(если надо). Пока процесс запущен, на его страницах может появляться новая информация -> тоже уведомление
Когда процесс получается page fault -> fault обработчику выясняет, какая виртуальная страница нужна и посылает сообщение внешнему pager.  Он читает эту страницу из диска, и копирует ее в свое адресное пространство. Далее он говорит fault обработчику, где находится страница на диске. Далее fault обработчик открепляет в таблице cтраниц старый адрес страницы и говорит MMU сделать новый. После этого перезапускается процесс.
Алгоритм замены страниц не может полностью находиться в внешнем pager - у него нет доступа к таблице страниц - к reference битам. Тогда либо надо запускать алгоритм в ядре, либо доставлять эти биты до внешнего pager.
Главный + такого подхода - код разбивается на модули и становится более гибким. Главный - лэйеризация создает дополнительные затраты на переходы и user в ядро. 
Каждый процесс может иметь свой pager - это позволяет разным процессам использовать разные политики управления памятью
