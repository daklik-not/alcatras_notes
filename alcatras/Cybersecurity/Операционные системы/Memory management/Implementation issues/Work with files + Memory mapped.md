Для работы с файлом в классическом случае, то есть через системные вызовы read/write, есть определенный алгоритм.
1. Данные с файла копируются в Paging Cache - кэш страниц. Кэш страниц - это не кэш процессора - это просто память в RAM. Ее особенность в том, что данные оттуда удаляются только, если RAM полностью заполнена. Также это kernel-level память - то есть кэшем страниц управляет ядро.
2.  После этого данные еще раз копируются в пользовательский буфер - мапятся -> процесс может работать с файлом
Проблема такого подхода в том, что данные хранятся и в кэше страниц и в пользовательском буфере - двойные затраты по памяти - невыгодно

Есть другой подход - **MMF - Memory Mapped Files**
Страничные кадры кэша страниц напрямую проецируются в виртуальную память - таблицы страниц.  Тогда данные хранятся в единичном экземпляре.
Для того чтобы выделить такую память используется **mmap**
Она разделяется на **private** - доступна только одному процессу и **shared** доступна нескольким процессам.

Есть вообще Direct IO но у него много минусов, включая нагрузку на дисковую системы, отсутствие OS синхронизации и другие.
