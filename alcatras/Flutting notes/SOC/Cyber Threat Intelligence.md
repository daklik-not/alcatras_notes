CTI помогает отвечать на вопросы:
1. Кто, что, вызвало алерт
2. Как они вели себя в прошлом
3. Что я должен сделать прямо сейчас

Литература информационной безопасности разделяет все на:
1. Данные. Например IP+port -> артефакт
2. Полный контекст происходящего, например, чей это IP или время алерта
3. Что дает вся эта информация в общем - например гипотеза о том что IP принадлежит известной хакерской группировке.1

Вообще процесс получения данных называется *enrichment*. 
Данные подразделяются еще на 3 категории:
1. IOC - indicator of compromise, например C2 адрес
2. IOA - вредоносное действие(indicator of attack)
3. TTP - tactics, techniques, procedures

Какие индикаторы надо смотреть в 1 очередь:
1. IP адрес
2. Domain
3. Url
4. File hash
5. Email address
6. Local artefact

Intelligence не строится с нуля. Происходит следующим образом. Провайдер **фидов(индикатор по которому будет реагировать)** шлет тебе фид. Далее тебе нужно решить - буду ли я встраивать этот фид в **платформу**. Платформа это готовая настроенная база фидов - без ложных, устаревших фидов.  К тому же в ней хранится почему этот фид проблемный - например, когда последний раз этот адрес был вредоносным ну или че то такое. Задача аналитиков время от времени обновлять эту базу.
Короче это работает так: SIEM берет из OpenCTI(например) индикаторы, которые подставляются в правила, по которым будут срабатывать алерты. Далее приходит alert, с которым SOC идет опять в OpenCTI, но смотрит там уже не просто артефакт на который срабатывает, а почему на него срабатывает - максимально подробная информация об индикаторе.
#### CTI Lifecycle
На картинке представлено, как можно распространять полученную Intel информацию:
![[deepseek_mermaid_20261008_973478.png|352]]

Сам Lifecycle:1
1. *Direction* - Понимание чего мы хотим от внедрения CTI.
2. *Collection* - фиды, данные о фидах, данные о недавних атаках и тд.
3. *Processing* - нормализация данных из разных источников.  корреляция данных из различных источников между собой. Например к нормализации относится приведение IP адресов в 1 формат, а к корреляции - настройка CTI платформы так, чтобы старые данные и новые не противоречили друг другу(ну или просто убираем старые).
4. *Analysis* - нужно убедиться в том, что правила рабочие. Например это можно судить по частоте срабатывание правила с индикатором. + надо настроить приоритезацию правил
5. *Dissemination*  - короче смысл в том, чтобы распространять по компании полученные правила неодинаково. Каждой команде нужен свой формат
6. *Feedback* - через время понять насколько эффективнее стала работа.

INTEL информация передается в 2 форматах:

# File and Hash Threat Intel
#### File Path
Стандартный пути для записи файлов:
```
C:\
C:\Users\Public
C:\Users\Public\Public Downloads
C:\Windows\Temp\
C:\ProgramData\
```

Но злоумышленники тоже маскируют файлы:
```
invoice.pdf.exe // подмена расширения
scvhost.exe // маскируется под легальные процессы
jh8F21.exe // названия с высокой энтропией
backup-2300.exe // файлы с названиями похожие на нормальные
```

#### Dynamic analysis
Используется *sandboxing*, после выполнения извлекаются артефакты, смотрится импакт на тестируемую систему.  Самые часто-используемые онлайн-песочницы:
1. Hybrid analysis - фокусируется на дереве поведения и MITRE ATTACK.
2. Joe Sandbox - максимально подробная песочница

Проблема в том, что:
1. малвари умеют понимать, что они в песочнице. 
2. время анализа в песочницах сильно ограничено - где то уже писал про sleep вызовы после каждой инструкции
3. многие песочницы не могут дешифровать SSL/TLS трафик, что приводит к слепым зонам
4. LotL malware - тоже плоховато отслеживается

# IP and Domain Threat Intel
Инструменты для проверки резолва + географического положения IP адреса за DNS сервером:
1. [nslookup.io](https://www.nslookup.io/), [dnschecker.org](https://dnschecker.org/).
2. [RDAP.ORG](https://about.rdap.org/). Самое важное что она показывает возраст. У вредоносных доменов срок жизни чаще всего очень маленький

Помимо A/AAAA записей нас интересует TXT запись. Де-факто она не обязательна - злоумышленник может ее не заполнять. Но легитимные компании часто указывают в ней, почту - SPF, DKIM. Пустая, или с подделанными SPF, DKIM

Проблемы:
1. За доменным именем может быть еще CDN. Тогда IP ничего не дает
2. Похожие названия в именах доменов - например, когда используются кириллическая a вместо латинской. Использовать https://www.punycoder.com/

Чтобы проверить является ли IP вредоносным:
1. [AbuseIPDB](https://www.abuseipdb.com/):
2. [VirusTotal](https://www.virustotal.com/)
3. [BGP.Tools](https://bgp.tools/)
4. [ipinfo.io](https://ipinfo.io/), [iplocation.net](https://iplocation.net/) - географическое положение IP адреса

Иногда хочется узнать побольше про то, какие сервисы на этом IP экспознуты в интернет. Также можно посмотреть на IP атакующего.
Есть специальные инструменты разведки:
1. [Shodan](https://www.shodan.io/)
2. [Censys.io](https://search.censys.io/)

Если экспознут веб-сервер на IP можно узнать много всего из сертификата. Сайты:
1.  [crt.sh](https://crt.sh/)
2.  [SSL Shopper](https://www.sslshopper.com/ssl-checker.html).

Чтобы точно знать, что устройство реально находится по тому, адресу надо убедится что устройство не использует VPN или прокси. Есть инструменты:
1. https://spur.us/
2. [Spur](https://spur.us/)

Сначала расследуем домен, потом расследуем IP.
