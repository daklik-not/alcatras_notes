Вообще DoS атаки есть на многих уровнях модели OSI.  Тот же SYN flood например. 
DoS атака с 1 устройства и может быть разная - просто инпут который ломает систему, можно флудить маленькими запросами, можно отправить 1 очень большой запрос. 
DDoS это с нескольких устройств.  Армия скомпроментированных устройств называется *botnet*.  По инструкции они начинают флудить.  Есть несколько типов.
1. Showloris. Посылаются неполные http запросы без \r\n\r\n. Соединение продолжает висеть. Потом этих соединение становится слишком много - сервер перестает отвечать. 
2. HTTP флуд. Просто шлем очень много HTTP запросов. 
3. Cache Bypass.  Обходим CDN сервера, чтобы отвечал напрямую искомый сервер.  Самое простое это найти реальный IP сервера и обращаться по нему а не по доменному имени
4. Oversized query - когда отправляем запросы с большим содержанием. 
5. Login form abuse. Перенагружаем логику аутентификацию попытками авторизации/сбросом пароля 
6. Faulty Input Validation Abuse - когда инпут плохо валидируется можно попробовать отправить что-то что сломает систему. 

#### Логи
Каждый тип сервера хранит логи.  Ниже то что нужно искать в логах. 
1. Высокая частота запросов авторизации. Например веб-запросы к странице /login.
2. Странные user-agent.  хз насколько это актуально, потому что user-agent легко меняется. Есть такая штука  - TLS отпечаток.  По ней можно попробовать понять с какого клиента отправляется запрос.  tls.handshake.ja4. Но я потыкал, там вроде оно тоже так себе определяет
3.  Запросы с IP по всему миру. 
4.  Спайки запросов. 
5. Спайки 50(3-11) - *service unavailable*.
6. Абуз логики.  Например GET /products?limit=999999 вытащит слишком много продуктов с базы данных. 

Злоумышленник будет нацелен на ресурсы, которые потребляют больше всего ресурсов на запрос.
/login, /search, /api, /register, /signup, /contact, /feedback, /cart(корзина типо) /checkout.
