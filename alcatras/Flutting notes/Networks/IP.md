Есть 3 типа канального уровня. 
1. LAN - обычная домашняя сеть. В ней разрешен мультикаст и броадкаст. Для получения мак адреса устройства в LAN устройство броадкастит(APR). Ему приходит ответ и далее оно обращается в локальной сети по мак адресу устройства.
2. Point To Point.  Это обычная передача между устройством и маршрутизатором. 2 устройства соединены напрямую, никакой адресации не требуется.
3. NBMA. Аналогично LAN но запрещен броадкаст и мультикаст..

### IPv4
1. ненадежное *connectionless* соединение.
2. данные передаются датаграммами
3. используется поверх всех канальных уровней
4. пакеты различной длины

255.255.255.255 - пример IP адреса
У роутера столько IP, сколько интерфейсов. Например если поддерживается беспроводная и проводная, то будет 2 IP(*multihomed*)

![[Cache/Pasted image 20260606131924.png]]
Обмениваясь в локальной сети мы можем просто положить IP пакет в payload фрейма и отправить по нужному MAC адресу.

Когда надо отправить на удаленный хост, то устройство посылает пакет на в фрейме на роутер. IP адреса группируются в подсети - набор адресов с 1 и тем же префиксом.

#### IPV4 пакеты
![[Cache/Pasted image 20260606175935.png]]
1. *Version* - версия IP протокола
2. *IHL - IP Header Length*. Показывает \[длину всего заголовка  /  4 байта\] в 4-битном поле.
3. DS ??
4. *Protocol* - показывает транспортный протокол, который должен обработать пэйлоад пакета по адресу назначения. (6 для TCP и 17 для UDP)
5. *length* - длина всего IPV4 пакета
6. *source* адрес
7. *destination* адрес
8. *checksum* - она защищает только IPv4 заголовки от ошибок передачи
9.  *TTL - Time To Live* - защищает от бесконечного цикла пересылок 
***Фрагментация***
Для IP интересен максимальный размер кадра канального уровня поверх которого она работает - они разные - *MTU*. Если посланный пакет окажется слишком большим, IPv4 использует фрагментацию пакетов. 
Большой пакет фрагментируется на 2 или более фрагментов. Размер всех фрагментов равен MTU, кроме последнего. В пакете устанавливается *Identification* поле, которое позволяет идентифицировать эти пакеты среди остальных. Поле *Fragment Offset* позволяет идентифицировать позицию пэйлоада в последовательности.. *Length* показывает длину пэйлоада фрагмента. *More* устанавливается только в последнем  фрагменте.
```c
if p.len <  mtu :
 send(p) // пэйлоад меньше mtu
maxpayload=8*int((mtu-20)/8)  // максимальный размер пэйлоада, must be кратен 8 байтам
if p.flags=='DF' : // запрещено фраментирование - игнорируем
 discard(p)
payload=p[IP].payload 
pos=0
while len(payload) > 0 :
 if len(payload) > maxpayload :
    toSend=IP(dest=p.dest,src=p.src,
              ttl=p.ttl, id=p.id,
              frag=p.frag+(pos/8),
              len=mtu, proto=p.proto)/payload[0:maxpayload]
    pos=pos+maxpayload
    payload=payload[maxpayload+1:]
 else
    toSend=IP(dest=p.dest,src=p.src,
              ttl=p.ttl, id=p.id,
              frag=p.frag+(pos/8),
              flags=p.flags,
              len=len(payload), proto=p.proto)/payload
 forward(toSend)
```
Дефрагментация. Сначала проверяем является ли пакет фрагментом - смотрим значение *More* и  *Fragment Offset*. Если *Fragment Offset == 0*, и *More* скинут, то полученный пакет на фрагментирован. Использует *Identification* поле, чтобы понять к какому пакету относится текущий пакет. Есть таймер, после его истечения пакеты больше не деассемблируются.
